# セキュリティ用メールの確認

## アドレスの変更

**アカウントセキュリティ**で非公開メールアドレスを編集します。メール送信が有効な場合、保存すると新しいアドレス宛ての確認メールがキューに追加されます。8桁のコードを入力すると変更が反映されます。確認が完了するまでは現在のアドレスが利用できます。メール送信が無効な場合は、保存時に直接更新されます。

どちらの方法にも、設定済みのブラックリストまたはホワイトリストが適用されます。メール送信が無効な場合も同様です。ルールは完全なアドレスまたはドメインに一致し、サブドメインは別に扱います。同じ国際化ドメインのUnicode表記とPunycode表記は同じルールに一致します。他のアカウントが使用中のアドレスや、閉鎖済みアカウントのために予約されているアドレスは取得できません。

## 確認API

これらの操作には現在のブラウザCookieが必要です。JSON本文には `Content-Type: application/json` を指定し、上限は4,096バイトです。

| メソッド | パス | リクエストまたはレスポンス |
|---|---|---|
| GET | `/api/auth/profile/security` | `email` と `email_verification_required` を含む |
| PUT | `/api/auth/profile/email` | `{"email":"new@example.com"}`。キュー追加時は `202` と `{id,status,ticket}`、それ以外は `200` とアカウントセキュリティ |
| POST | `/api/auth/profile/email/confirm` | メールとコード。`200` と更新後のアカウントセキュリティ |
| GET | `/api/auth/mail/:id` | 配信状態。要求元アカウントまたは `X-Renop-Mail-Ticket` でアクセスを認可 |

```json
{"email":"new@example.com","code":"01234567"}
```

コードの有効期限は10分で、誤入力は5回までです。要求元のブラウザセッションに紐づきます。60秒後に新しいコードを要求できますが、IP別の送信制限も適用されます。新しいメールが正常にキューへ追加されると以前のコードは無効になります。追加に失敗した場合、以前のコードは維持されます。コード保存、キュー追加、IP制限の計上は同一トランザクションで確定します。

誤ったコード、期限切れ、使用済み、または状態が変化したコードには `400` と `ACCOUNT_EMAIL_CODE_INVALID` を返し、ブラウザのログイン状態は維持します。使用中のアドレスには `409` と `ACCOUNT_EMAIL_CONFLICT`、宛先ポリシーによる拒否には `400` と `mail_recipient_blocked` を返します。失効したセッションでは変更を確定できません。認証情報やセキュリティ設定の変更も保留中の確認を無効にします。

## GitHubによる確認

GitHubログインが設定されている場合、**GitHubの確認済みメールを使用**から `GET /api/auth/github/start?intent=email` を通じて最新の取得を許可できます。この処理は `user:email` を要求し、[認証済みGitHubユーザーのメール一覧](https://docs.github.com/en/rest/users/emails#list-email-addresses-for-the-authenticated-user)を読み取ります。

RenoPは確認済みのプライマリ連絡先アドレスを選択し、プライマリがなければ最初の確認済み連絡先を選びます。GitHubのno-replyアドレスは除外します。取得したアドレスをローカルの宛先ポリシーで確認して保存します。送信アカウントが未設定でも利用でき、GitHubログインの連携を作成したり置き換えたりすることはありません。

コールバックは1回限りで、有効期限は10分です。開始時と同じアカウントおよびブラウザセッションへ戻り、認証情報が変わっていない必要があります。プロバイダーのアクセストークンはこの取得にのみ使用し、保持しません。

## 運用

RenoPは最大2,048件の保留中メール変更を保持します。期限切れのレコードは追加前とメールのクリーンアップ時に削除します。コードは鍵付きハッシュとして保存し、キュー内のメール本文は非公開のメール暗号化キーで暗号化します。コードと配信チケットをURL、ログ、ブラウザストレージに保存しません。

変更が成功するとプロフィールのアクティビティを記録します。直列のメールワーカーが設定されたルーティングと送信制限に従って `email_changed` 通知を送信します。キューへの追加と配信完了は異なります。確認ダイアログにはプロバイダーの配信状況と失敗を表示します。
