# セキュリティ用メールの確認

## アドレスの変更

**アカウントセキュリティ**で非公開メールアドレスを編集します。メール送信が有効な場合、保存すると新しいアドレス宛ての確認メールがキューに追加されます。8桁のコードを入力すると変更が反映されます。確認が完了するまでは現在のアドレスが利用できます。メール送信が無効な場合は、保存時に直接更新されます。

どちらの方法にも、設定済みのブラックリストまたはホワイトリストが適用されます。メール送信が無効な場合も同様です。ルールは完全なアドレス、完全一致の @domain、サブドメインを含む .suffix を指定できます。拒否リストモードでは内蔵の一時メールリストも利用でき、許可リストモードでは無視します。同じ国際化ドメインのUnicode表記とPunycode表記は同じルールに一致します。他のアカウントが使用中のアドレスや、閉鎖済みアカウントのために予約されているアドレスは取得できません。

## ログイン用メールの別名

メインと追加のメールは同じ一意のアカウント所有記録を使用します。外部 ID または返された連絡先のいずれかが他のアカウントに属する場合、退会後の保留期間中のアドレスも含め、連携は失敗します。連携、アドレスの予約、セキュリティ変更は同じトランザクションで確定し、失敗しても既存アカウントは変わりません。メールによるアカウント統合は行いません。

「その他のログイン用メール」には非公開の追加アドレスが表示されます。同じアカウントのパスワードや Passkey によるログイン、メールでのパスワード再設定、オフライン復旧コードに使用できます。既存のパスワードと二次認証ポリシーはそのまま適用されます。通知は引き続きメインのメールに送信します。アカウントごとにメインを含め最大128件を保持できます。

返されたアドレスはプロバイダーで確認済みであるか、ログイン中のアカウントにすでに属している必要があります。それ以外はプロバイダーで確認するか、「メールを追加して確認」を使ってから連携してください。追加には RenoP のメール配信と既存の確認コード画面を使用します。未確認のプロバイダーメールで登録する場合、そのアドレスの確認が必要です。別のアドレスの確認では代用できません。GitHub の no-reply アドレスは対象外です。

連携解除後もメールの別名は残ります。別名を削除するとアドレスは解放されますが、後のプロバイダー認可で再追加される場合があります。メインのメールは別名削除操作では削除できません。利用停止中はすべてのアドレスを保持し、退会後はメインが未設定の場合もすべて14日間予約します。管理者による早期解放は保持中の全アドレスに適用します。

| メソッド | パス | リクエストまたは応答 |
|---|---|---|
| GET | `/api/auth/profile/security` | `email` に加えて `email_aliases` を返す |
| PUT | `/api/auth/profile/email` | `{"email":"alias@example.com","alias":true}`。確認受付情報と `202` |
| DELETE | `/api/auth/profile/email/alias` | `{"email":"alias@example.com"}`。更新後のセキュリティ情報 |

別名の確認には既存の確認 API を使用します。用途はチャレンジとともに保存され、確認リクエストでは変更できません。削除には5分以内にログインしたブラウザーセッションが必要です。`ACCOUNT_EMAIL_PROOF_REQUIRED`、`ACCOUNT_EMAIL_LIMIT`、`ACCOUNT_EMAIL_PRIMARY` は `409` を返し、削除時の古いセッションには `MFA_REAUTH_REQUIRED` を返します。

アップグレードでは既存のメインメールの所有記録を補完します。以前は外部メールを保存していなかったため、既存の連携からは次回の認可時に別名を取得します。新しいブラウザーセッションを保存する前に、アカウントのトランザクション内で利用停止と有効期限を再検証します。

## 確認API

これらの操作には現在のブラウザCookieが必要です。JSON本文には `Content-Type: application/json` を指定し、上限は4,096バイトです。

| メソッド | パス | リクエストまたはレスポンス |
|---|---|---|
| GET | `/api/auth/profile/security` | `email` と `email_verification_required` を含む |
| PUT | `/api/auth/profile/email` | `{"email":"new@example.com"}`。キュー追加時は `202` と `{id,status,ticket}`、それ以外は `200` とアカウントセキュリティ |
| POST | `/api/auth/profile/email/confirm` | メールとコード。`200` と更新後のアカウントセキュリティ |
| GET | `/api/auth/mail/:id` | 配信状態。要求元アカウントまたは `X-Renop-Mail-Ticket` でアクセスを認可 |

```json
{"email":"new@example.com","code":"01234567"}
```

コードの有効期限は10分で、誤入力は5回までです。要求元のブラウザセッションに紐づきます。60秒後に新しいコードを要求できますが、IP別の送信制限も適用されます。新しいメールが正常にキューへ追加されると以前のコードは無効になります。追加に失敗した場合、以前のコードは維持されます。コード保存、キュー追加、IP制限の計上は同一トランザクションで確定します。

誤ったコード、期限切れ、使用済み、または状態が変化したコードには `400` と `ACCOUNT_EMAIL_CODE_INVALID` を返し、ブラウザのログイン状態は維持します。使用中のアドレスには `409` と `ACCOUNT_EMAIL_CONFLICT`、宛先ポリシーによる拒否には `400` と `mail_recipient_blocked` を返します。失効したセッションでは変更を確定できません。認証情報やセキュリティ設定の変更も保留中の確認を無効にします。

## GitHubによる確認

GitHubログインが設定されている場合、**GitHubの確認済みメールを使用**から `GET /api/auth/github/start?intent=email` を通じて最新の取得を許可できます。この処理は `user:email` を要求し、[認証済みGitHubユーザーのメール一覧](https://docs.github.com/en/rest/users/emails#list-email-addresses-for-the-authenticated-user)を読み取ります。

RenoPは確認済みのプライマリ連絡先アドレスを選択し、プライマリがなければ最初の確認済み連絡先を選びます。GitHubのno-replyアドレスは除外します。取得したアドレスをローカルの宛先ポリシーで確認して保存します。送信アカウントが未設定でも利用でき、GitHubログインの連携を作成したり置き換えたりすることはありません。

コールバックは1回限りで、有効期限は10分です。開始時と同じアカウントおよびブラウザセッションへ戻り、認証情報が変わっていない必要があります。プロバイダーのアクセストークンはこの取得にのみ使用し、保持しません。

## 運用

RenoPは最大2,048件の保留中メール変更を保持します。期限切れのレコードは追加前とメールのクリーンアップ時に削除します。コードは鍵付きハッシュとして保存し、キュー内のメール本文は非公開のメール暗号化キーで暗号化します。コードと配信チケットをURL、ログ、ブラウザストレージに保存しません。

変更が成功するとプロフィールのアクティビティを記録します。直列のメールワーカーが設定されたルーティングと送信制限に従って `email_changed` 通知を送信します。キューへの追加と配信完了は異なります。確認ダイアログにはプロバイダーの配信状況と失敗を表示します。

他のプロバイダーもプロフィール編集画面で[確認済みメールを使用](./oauth-login.md)を提供できます。この操作も新しい認可を要求し、現在のログイン連携を保持して宛先ポリシーを適用します。明示的な確認済みクレームがない場合は、RenoP のメールコードで確認してください。
## アカウントの言語

ログイン時に、各端末でアカウントに保存された言語を復元します。未設定のアカウントには現在の表示言語を採用し、その後の言語選択は自動保存します。登録時にはページの言語を新しいアカウントと一緒に保存します。保存に失敗した場合、未送信の選択を端末に 1 件保持し、再接続、ページへの復帰、再読み込み時に再試行します。以前のアカウントの選択を別のアカウントに適用することはありません。

言語設定は非公開で、ユーザー名変更や再起動後も保持され、アカウント削除時に消去されます。変更しても認証情報や進行中の二段階認証は無効になりません。自動通知とパスワード再設定メールには受信者の設定を使用し、メール別名でアカウントを識別した場合も同様です。未設定の場合は操作元ページの `Accept-Language`、続いて `en-US` を使用します。キュー内のメールは追加時の言語を保持します。

対応する識別子は `en-US`、`zh-CN`、`zh-HK`、`zh-TW`、`zh-YUE`、`ko-KR`、`ja-JP`、`de-DE`、`fr-FR`、`ru-RU`、`es-ES`、`pt-PT` です。

| メソッド | パス | リクエストまたはレスポンス |
|---|---|---|
| GET | `/api/auth/profile/locale` | `{"user_id":"00000000-0000-4000-8000-000000000001","locale":"fr-FR"}`。空値は未設定を表します |
| PUT | `/api/auth/profile/locale` | `{"user_id":"00000000-0000-4000-8000-000000000001","locale":"fr-FR"}`。保存された正規の識別子を返します |

どちらも現在のブラウザー Cookie が必要で、言語設定のレスポンスには `Cache-Control: no-store` を付けます。API トークンでの読み取りや変更はできません。未対応の値には `400` と `ACCOUNT_LOCALE_INVALID` を返します。[メール設定](../configuration/mail.md)には全体の言語を手動選択する項目はありません。

PUT には GET が返す不変の `user_id` を指定します。アカウントが一致しない場合は `403` を返します。端末の未送信の選択もこの ID に結び付くため、ユーザー名の変更や再利用で別のアカウントに設定が引き継がれることはありません。
