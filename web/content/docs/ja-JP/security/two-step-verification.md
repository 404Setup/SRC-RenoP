# 2段階認証

## ログイン時の動作

アカウントのセキュリティパネルで2段階認証を設定します。パスワードまたは外部アカウントの認証後、設定済みの追加認証を完了してからブラウザーセッションが発行されます。認証アプリと追加認証用の Passkey が両方有効な場合は、どちらかを使用できます。追加認証用の Passkey だけではログインできません。通常の Passkey ログインの後に認証アプリのコードを要求することもできます。

追加認証が必要な場合、パスワードまたは通常の Passkey ログインは `409` と `X-Renop-Error-Code: MFA_REQUIRED` を返します。GitHub はローカルの `return_to` を保持して `/account/login?mfa=1` に戻ります。非公開の HttpOnly `renop_mfa` Cookie は保留中の認証エンドポイントだけを許可し、ブラウザーセッションにはなりません。チャレンジは5分間有効で一度だけ使用でき、再起動時に破棄されます。プロセス全体で最大4,096件、アカウントごとに8件を保持します。

## 認証アプリの設定

「認証アプリ」の横の「設定」を選択します。QR コードを読み取るか、表示されたキーを時間ベース、SHA-1、6桁、30秒周期で手動登録します。QR 画像は RenoP が生成し、設定情報を外部の QR サービスに送信することはありません。5分以内にアプリのコードを入力して確認してください。未確認の設定ではログインポリシーは変更されません。

コードは [RFC 6238](https://www.rfc-editor.org/info/rfc6238/) に従い、サーバー時刻の前後1周期を許容します。サーバーと端末の時計を同期してください。設定確認を含め、使用済みの周期は再利用できません。必要に応じて次のコードを待ってください。アカウントごとの5分間の枠で5回失敗すると、その枠が終了するまでコードの試行を受け付けません。新しいログインチャレンジを取得しても制限はリセットされません。

## Passkey を追加の認証に使用

「Passkey を追加の認証に使用」を有効にする前に、アカウントに Passkey を登録してください。最初の認証としてパスワードまたは連携済みの外部アカウントを残す必要があります。RenoP は最後の初回ログイン方法の無効化と、この設定が有効な状態で最後の追加認証用 Passkey を削除する操作を拒否します。最後の Passkey を削除する前に設定を無効にしてください。追加認証のアサーションには WebAuthn のユーザー検証が必要です。

## 認証 API

以下の JSON POST/PUT 本文には `Content-Type: application/json` が必要で、上限は4,096バイトです。プロフィールの変更には現在のブラウザー Cookie と5分以内のログインが必要です。古いセッションには `MFA_REAUTH_REQUIRED` を返します。変更が成功すると他のブラウザーセッションは失効します。セキュリティ状態には真偽値 `totp_enabled` と `passkey_second_factor` が追加されますが、認証キーは含まれません。

| メソッド | パス | JSON 本文または結果 |
|---|---|---|
| GET | `/api/auth/mfa` | `{totp,passkey,expires_at}` |
| DELETE | `/api/auth/mfa` | `204` |
| POST | `/api/auth/mfa/totp` | `{"code":"012345"}` |
| POST | `/api/auth/mfa/passkey/begin` | `{}` → `{options}` |
| POST | `/api/auth/mfa/passkey/finish` | `{credential}` → session |
| POST | `/api/auth/profile/mfa/totp/begin` | `{}` → `{id,secret,uri,qr,expires_at}` |
| POST | `/api/auth/profile/mfa/totp/confirm` | `{"id":"setup-id","code":"012345"}` → security |
| PUT | `/api/auth/profile/mfa` | `{"passkey_second_factor":true}` または `{"totp_enabled":false}` → security |

```json
{"totp_enabled":true,"passkey_second_factor":true}
```

コード、QR 画像、設定キー、チャレンジ Cookie を URL、ログ、ブラウザーストレージに保存しないでください。認証エラーは `MFA_INVALID`、サービス障害は `MFA_UNAVAILABLE`、追加認証用 Passkey 単独でのログインは `MFA_PRIMARY_REQUIRED` を返します。認証に成功すると JSON 形式のセッション情報を返し、通常の HttpOnly セッション Cookie を設定します。

## 復旧と運用

未使用のオフラインリカバリーコード4個による復旧は、パスワードの再設定、認証アプリの削除、Passkey の追加認証の無効化、全ブラウザーセッションの失効を同一トランザクションで行います。登録済み Passkey は引き続き連携され、通常のログインに利用できます。メールによるパスワード再設定では2段階認証は維持されます。コードを安全に保管し、復旧後に2段階認証を設定し直してください。

追加認証を有効にしたアカウントでは、パッケージクライアントと自動化に API トークンが必要です。プロトコルの認証ではアカウントのパスワードを拒否します。既存のスコープ付きトークンと移行済みアップロードトークンは各権限に従って使用できます。2段階認証を無効にすると、パスワードログインが有効な場合はプロトコルでのパスワード使用が再び可能になります。

RenoP は起動時に設定の最上位に非公開の `mfa_encryption_key` を作成します。認証アプリのキーは AES-GCM で暗号化され、不変のユーザー ID に関連付けられます。暗号化キーは設定レスポンスに含まれません。データベースと設定を一緒にバックアップし、移行時もこのキーを保持してください。キーを失うとアプリによる認証ができなくなるため、オフラインリカバリーコードでアクセスを復旧してください。
