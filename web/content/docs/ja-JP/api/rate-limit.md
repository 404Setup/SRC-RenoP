# レート制限と防御

RenoP は複数段階のレート制限と異常検知を組み合わせ、総当たり攻撃、サービス妨害、過剰な自動収集を
抑制します。

## 匿名アクセスの制限

未認証リクエストは、クライアント IP ごとにスライディングウィンドウとトークンバケットで評価されます。

- 公開成果物のダウンロードには比較的余裕のある上限を適用します。
- 検索とメタデータにはより厳しい上限を適用し、超過時は `429 Too Many Requests` を返します。

## 認証失敗と IP ブロック

- 無効な資格情報やログイン試行による `401 Unauthorized` または `403 Forbidden` を IP ごとに集計します。
- 10 回の失敗後、後続のリクエストは `403 Forbidden` になります。最後に集計された失敗から五分後に
  カウンターは失効し、ブロックされたリクエストはこの期間を延長しません。
- 匿名の認証要求と有効なセッションに対する権限不足は集計しません。画面と静的リソースは引き続き利用できます。

## 同時実行数 (`max_active_requests`)

`config.yaml` の `server.max_active_requests` を設定します。既定値は 512 です。

- 実行中リクエストが上限に達すると、新しいリクエストは `503 Service Unavailable` になります。

## 信頼するプロキシ

リバースプロキシまたは CDN の背後では、`config.yaml` の `server.trusted_proxies` と
`server.cdn_ip_header` を設定します。RenoP は信頼済み送信元から検証した実クライアント IP のみを
レート制限に使用します。
