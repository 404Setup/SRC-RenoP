# レート制限

グローバル ミドルウェア `AnomalyMiddleware`（`middleware/anomaly.go`）はルート ハンドラの前に実行されます。

制御は次の順で適用されます。

1. 同時リクエスト上限（プロセス全体）
2. 認証失敗によるバン（クライアント IP 単位）
3. 匿名リクエストのレート制限（クライアント IP 単位、トークンバケット）

制限が適用されるとき、応答に `Connection: close` が設定されることがあります。

## クライアント IP

制限のキーは `utils.ExtractIP` が返すクライアント IP です。

- 既定: peer アドレス（`c.IP()`）。
- peer が loopback（`127.0.0.1` / `::1`）または `server.trusted_proxies` に含まれ、かつ `server.cdn_ip_header`
  が設定されている場合、そのヘッダからクライアント IP を取得します。複数値ヘッダは右から左へ走査し、trusted hop はスキップします。

プロキシ信頼の設定が誤っていると、複数クライアントが同一 IP
に写像される（またはその逆）ことがあります。[settings.md](./settings.md) を参照してください。

Cloudflare → Caddy → RenoP では `cdn_ip_header` を `CF-Connecting-IP` に設定します。loopback peer に `trusted_proxies`
エントリは不要です。

## 1. 同時リクエスト上限

| 設定                         | 既定   | 効果                   |
|------------------------------|--------|------------------------|
| `server.max_active_requests` | `2000` | プロセス内の最大同時数 |

- ミドルウェアに入るすべてのリクエストを数えます（認証済みおよび静的リソースを含む）。
- 現在の件数が上限を超える場合、 **`503 Service Unavailable`** を返します。
- 設定値 `0` は読み込み時に `2000` に正規化されます。このフィールドに無制限モードはありません。

サーバ起動時、Fiber 自身の同時実行上限も同じ値に設定されます。

## 2. 認証失敗バン（IP 単位）

| 定数                   | 値   | 意味                                     |
|------------------------|------|------------------------------------------|
| `MaxFailuresPerMinute` | `5`  | バン前の失敗回数しきい値                 |
| Failure store TTL      | 5 分 | `AnomalyFailures` キャッシュの有効期間窓 |

**失敗として数える条件:** ハンドラ返却後、最終ステータスが **`401`** または **`403`** のとき、当該 IP の失敗カウンタを 1
増やします（キャッシュ内の 8 バイト little-endian 値）。

**バン動作:**

- リクエスト開始時点でカウンタがすでに **≥ 5** の場合、ハンドラを実行せずに **`403 Forbidden`** を直ちに返します。
- バン応答は `Next()` の前に生成されるため、カウンタは再加算されません。
- キャッシュ エントリの TTL は最終書き込みから **5 分** です。失敗を記録するたびに更新されます。期限切れ後にカウンタは削除されます。

下記の静的フロントエンド スキップ一覧以外のすべてのパスに適用されます（既に認証済みのクライアントも含む）。ハンドラが
401/403 を繰り返し返すと IP がバンされ、以降のリクエストの credential には依存しません。

注: 定数名は “per minute” を含みますが、ストア窓は **5 分** です。カウンタはエントリ期限まで増加のみします。

## 3. 匿名リクエストのレート制限（IP 単位）

`golang.org/x/time/rate` によるトークンバケット。IP ごとに 1 つの limiter（`GlobalIPLimiter`）。

| 定数                   | 値    | 意味                                            |
|------------------------|-------|-------------------------------------------------|
| `MaxRequestsPerMinute` | `100` | 持続レート: 毎分 100 トークン（約 600 ms に 1） |
| `MaxRequestsBurst`     | `60`  | バースト容量（同時に保持できる最大トークン数）  |

- **制限対象:** 認証済みと検証されていないリクエスト（下記参照）。
- **免除:** 検証に成功した Session / Bearer / Basic、または有効な session / bearer に解決される GET/HEAD `?token=`。
- **超過時:** **`429 Too Many Requests`**。

### 免除に必要な認証

本番の認証キャリアと同じです（[authentication.md](./authentication.md)）:

| キャリア                                          | 検証される条件                             |
|---------------------------------------------------|--------------------------------------------|
| Cookie `renop_session` / `Authorization: Session` | セッションが存在し idle タイムアウト内     |
| `Authorization: Bearer <user>:<secret>`           | ユーザー名と secret が有効アカウントと一致 |
| `Authorization: Bearer <upload-token>`            | トークンが索引済みかつ未期限               |
| `Authorization: Basic …`                          | ユーザー名と password/secret が一致        |
| GET/HEAD `?token=`                                | 有効な session id または上記 bearer        |

無効な credential では免除されません。レート制限トークンは消費され、ハンドラの 401/403 は失敗カウンタにも加算されます。

idle 期限切れのセッションは認証済みとは扱いません（idle タイムアウトは約 7 日。認証ドキュメントを参照）。

### リミッタのライフサイクル

| 動作               | 詳細                                       |
|--------------------|--------------------------------------------|
| キー               | クライアント IP 文字列                     |
| idle 削除          | **5 分** 未使用のエントリを削除            |
| 定期クリーンアップ | **5 分** ごと                              |
| 緊急クリーンアップ | 格納 IP が **10,000** を超えると直ちに実行 |

## 静的フロントエンドのスキップ

**GET** および **HEAD** のみ。次のパスは認証失敗バンと匿名レート制限をスキップします。同時リクエスト上限には引き続き計上されます。

| パス          |
|---------------|
| `/`           |
| `/index.html` |
| `/assets/*`   |
| `/js/*`       |
| `/css/*`      |
| `/svg/*`      |

API ルート、Maven リポジトリ パス、その他の HTTP メソッドはスキップされません。

## ステータス コード

| コード | 条件                                 |
|--------|--------------------------------------|
| 429    | 匿名 IP がトークンバケット制限を超過 |
| 403    | 401/403 が多すぎて IP がバンされた   |
| 503    | プロセスの同時リクエスト上限を超過   |

応答本文は通常空です。`Retry-After` ヘッダーはありません。
