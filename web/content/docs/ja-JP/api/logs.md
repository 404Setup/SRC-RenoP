# 全体ログと操作履歴

## アクセス

管理ダッシュボードの **全体ログ**を開きます。システム管理者権限が必要で、API Token には `admin:audit`
も必要です。リポジトリのモデレーター権限だけでは利用できません。個人履歴は現在のアカウントに限定され、管理者は別のアカウントを参照できます。

開始者は操作を依頼したアカウント、操作者は実行したアカウントまたはシステムタスクです。既存の直接操作と過去の行では操作者を開始者として使います。個人ビューでは両方に同じ匿名化と絞り込みの制限を適用します。発生元は
`trigger` に保持します。改名と退会時の清掃は両方の身元を対象にします。

```http
GET /api/auth/logs?kind=system&severity=error&trigger=http&page=1&page_size=20
GET /api/auth/profile/audit-logs?action=LOGIN&from=1788739200000&until=1788825599999
GET /api/auth/users/alice/audit-logs?operator=admin&trigger=web
```

## フィルター

条件は AND で組み合わせます。文字列は完全一致、空欄は条件なしです。日時はブラウザーの現地時間から Unix ミリ秒に変換します。不正な条件は
`400` と `LOG_FILTER_INVALID` を返します。操作と発生元は 64 バイト、アカウントと操作者は 255 バイトまでです。

| パラメーター        | 値                                                                 |
|---------------------|--------------------------------------------------------------------|
| `kind`              | `audit`, `system`                                                  |
| `action`            | 操作 ID の完全一致、例 `LOGIN`, `SYSTEM_LOG`, `SYSTEM_HTTP_ERROR`  |
| `operator`          | ユーザー名の完全一致。個人ビューでは次も利用可能 `@administrator`  |
| `initiator`         | ユーザー名の完全一致。個人ビューでは次も利用可能 `@administrator`  |
| `username`          | 対象アカウント、全体ビューのみ                                     |
| `trigger`           | 発生元の完全一致 `web`, `api`, `http`, `system`, `unknown`         |
| `severity`          | `info`, `warning`, `error`                                         |
| `from`, `until`     | 境界を含む Unix ミリ秒。両端は省略可能                             |
| `page`, `page_size` | 既定値 `1`、`20`。ページサイズ `1`–`200`、オフセット最大 `1000000` |

## 公開範囲

既存の `AuditLogList` protobuf に `kind`、`trigger`、`initiator`、`severity` を追加しています。個人・指定アカウントの履歴は常に
`audit` に限定します。他の操作者は管理者として隠し、`operator=@administrator` でそのグループを選べます。他の名前を直接指定すると、存在しない名前も含めて
`400` となり、非公開の管理者名を推測できません。`username` でアカウントの範囲は広がりません。

## システム診断

バックグラウンドサービス起動後のプロセスログとHTTP サーバーエラーを記録します。診断詳細は一般の呼び出し元へ返しません。一般的なパスワード、認証ヘッダー、トークン、URL
ユーザー情報を保存前に隠し、各記録を 4096 バイトに制限します。既存の出力元は認証方法から発生元を決め、移行した過去の行は
`unknown` を使用します。非構造化ログはキーワードでレベルを推測し、構造化 HTTP エラーは `error` になります。

## 保持と書き込み

単一のコンシューマーが直列に保存し、正常終了時には元のログ出力を復元して 500
件のキューを処理します。満杯時の操作履歴は従来の同期保存を使います。システムログは元の出力に残り、失敗数を増やし、空きが戻ると超過通知を保存します。保存エラーは元の出力だけに書き、再帰を防ぎます。操作履歴は
`audit_log` の上限を保持し、システムログは別枠で最大 30 日・10000
件、より小さい設定があればその値を使います。十分ごとに清掃します。関連するシステム記録にも退会の保持期間と永久削除規則が適用されます。過去のプロセスログは取り込みません。
