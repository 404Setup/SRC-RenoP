# 速率限制与异常防护

全局中间件（`AnomalyMiddleware`）在每个请求到达路由处理器前运行。实现：
`middleware/anomaly.go`。

按顺序应用三项独立控制：

1. **并发请求上限** — 进程级
2. **认证失败封禁** — 按客户端 IP
3. **匿名请求速率限制** — 按客户端 IP（令牌桶）

触发限制时，响应可能设置 `Connection: close`。

## 客户端 IP

限制键来自 `utils.ExtractIP` 的客户端 IP：

- 默认：对端地址（`c.IP()`）。
- 若对端为环回地址（`127.0.0.1` / `::1`，本机 Caddy/nginx 常见）或在 `server.trusted_proxies` 中， **且** 设置了
  `server.cdn_ip_header`，则从该头解析客户端 IP（多值头从右向左跳过可信跳）。

代理信任配置错误可能把多用户映射到同一 IP（或相反）。见
[settings.md](./settings.md) 中的 server 配置。

Cloudflare → Caddy → RenoP 时，将 `cdn_ip_header` 设为 `CF-Connecting-IP` 即可；本机环回无需再写入 `trusted_proxies`。

## 1. 并发请求上限

| 设置                         | 默认   | 效果                 |
|------------------------------|--------|----------------------|
| `server.max_active_requests` | `2000` | 进程内最大在途请求数 |

- 计入进入中间件的 **所有** 请求（含已认证与静态）。
- 实时计数将超过上限时 → **`503 Service Unavailable`**。
- 配置中的 `0` 在加载时规范为默认（`2000`）；此字段无「无限」模式。

Fiber 自身的并发上限在服务器启动时与此值对齐。

## 2. 认证失败封禁（按 IP）

| 常量                   | 值     | 含义                                |
|------------------------|--------|-------------------------------------|
| `MaxFailuresPerMinute` | `5`    | 封禁前的失败计数阈值                |
| Failure store TTL      | 5 分钟 | `AnomalyFailures` BigCache 生命周期 |

**什么算失败**

处理器运行后，若最终状态为 **`401`** 或 **`403`**，则该 IP 的失败计数加一（缓存中 8 字节 little-endian 计数器）。

**封禁行为**

- 若请求开始时计数已 **≥ 5** → 立即 **`403 Forbidden`**（不运行处理器）。
- 封禁响应在 `Next()` 之前返回，因此 **不会** 再次增加计数。
- 缓存条目 TTL 为自上次写入起 **5 分钟**（每次记录失败会刷新条目）。过期后 计数消失，该 IP 可再试。

**范围**

适用于通过静态前端跳过（见下）的 **所有** 路径，包括已认证客户端。持续从处理器 获得 401/403 的客户端会触发封禁，与后续请求的凭证无关。

注：常量名写「per minute」，但存储窗口为 **5 分钟**，计数在条目过期前只增不减。

## 3. 匿名请求速率限制（按 IP）

通过 `golang.org/x/time/rate` 的令牌桶，每 IP 一个限流器（`GlobalIPLimiter`）。

| 常量                   | 值    | 含义                                          |
|------------------------|-------|-----------------------------------------------|
| `MaxRequestsPerMinute` | `100` | 持续速率：100 令牌 / 分钟（约每 600 ms 1 个） |
| `MaxRequestsBurst`     | `60`  | 突发容量（同时最多持有的令牌）                |

- **谁受限：** **未** 验证为已认证的请求（见下）。
- **谁豁免：** 成功验证的 Session / Bearer / Basic（或解析为有效会话或 bearer 的 GET/HEAD `?token=`）。
- **超限时：** **`429 Too Many Requests`**。

### 何为「已验证认证」

与生产认证传递方式相同（见 [authentication.md](./authentication.md)）：

| 传递方式                                          | 验证条件                        |
|---------------------------------------------------|---------------------------------|
| Cookie `renop_session` / `Authorization: Session` | 会话存在且在空闲超时内          |
| `Authorization: Bearer <user>:<secret>`           | 用户名 + secret 匹配有效账户    |
| `Authorization: Bearer <upload-token>`            | 令牌已索引且未过期              |
| `Authorization: Basic …`                          | 用户名 + 密码/secret 匹配       |
| GET/HEAD `?token=`                                | 令牌为有效会话 id 或上述 bearer |

存在但 **无效** 的凭证 **不** 豁免请求；仍消耗限流令牌，若处理器返回 401/403 还会 增加失败计数。

空闲过期会话不视为已认证（空闲超时 ≈ 7 天；见认证文档）。

### 限流器生命周期

| 行为     | 细节                               |
|----------|------------------------------------|
| 键       | 客户端 IP 字符串                   |
| 空闲淘汰 | **5 分钟** 未使用的条目移除        |
| 定期清理 | 每 **5 分钟**                      |
| 紧急清理 | 存储 IP 超过 **10,000** 时立即清理 |

## 静态前端跳过

仅对 **GET** 与 **HEAD**，下列路径跳过认证失败封禁与匿名限流（仍计入 并发上限）：

| 路径模式      |
|---------------|
| `/`           |
| `/index.html` |
| `/assets/*`   |
| `/js/*`       |
| `/css/*`      |
| `/svg/*`      |

API 路由、Maven 仓库路径及其他方法 **不** 跳过。

## 状态码（本中间件）

| 码  | 何时                       |
|-----|----------------------------|
| 429 | 匿名 IP 超过令牌桶速率限制 |
| 403 | 过多 401/403 后 IP 被封禁  |
| 503 | 进程并发请求上限已满       |

正文通常为空；信任状态码。当前无 `Retry-After` 头。

## 客户端建议

1. 高流量或脚本流量优先使用已认证访问（会话 cookie、Basic 或 Bearer），以免适用 按 IP 的匿名桶。
2. 避免紧密的登录 / 探测循环：同一 IP 上 **5** 次处理器级 **401/403** 可将该 IP 封禁最多 **约 5 分钟**。
3. 在反向代理或 CDN 后，正确设置 `trusted_proxies` 与 `cdn_ip_header`，使限流按真实 客户端而非代理计算。
4. 遇到 **429**，退避（如指数退避）后再重试未认证调用。
5. 本层返回 **503** 表示实例饱和；稍后重试，或在适当时扩展 / 提高 `max_active_requests`。
