# 速率限制

全局中间件 `AnomalyMiddleware`（实现见 `middleware/anomaly.go`）在路由处理器之前执行。

控制项按以下顺序应用：

1. 并发请求上限（进程级）
2. 认证失败封禁（按客户端 IP）
3. 匿名请求速率限制（按客户端 IP，令牌桶）

触发限制时，响应可能设置 `Connection: close`。

## 客户端 IP

限制所使用的键来自 `utils.ExtractIP` 解析的客户端 IP：

- 默认：对端地址（`c.IP()`）。
- 若对端为环回地址（`127.0.0.1` / `::1`）或位于 `server.trusted_proxies` 中，且已配置 `server.cdn_ip_header`，则从该请求头读取客户端
  IP。多值头从右向左扫描，并跳过可信跳。

代理信任配置不正确可能导致多个客户端映射到同一 IP，或出现相反情况。参见 [settings.md](./settings.md)。

Cloudflare → Caddy → RenoP 场景下，将 `cdn_ip_header` 设为 `CF-Connecting-IP` 即可；环回对端无需写入 `trusted_proxies`。

## 1. 并发请求上限

| 设置                         | 默认   | 效果                 |
|------------------------------|--------|----------------------|
| `server.max_active_requests` | `2000` | 进程内最大在途请求数 |

- 进入中间件的全部请求均计入（含已认证请求与静态资源）。
- 实时计数将超过上限时返回 **`503 Service Unavailable`**。
- 配置值为 `0` 时在加载阶段规范为 `2000`；该字段不提供无限模式。

服务器启动时，Fiber 自身的并发上限与此值对齐。

## 2. 认证失败封禁（按 IP）

| 常量                   | 值     | 含义                               |
|------------------------|--------|------------------------------------|
| `MaxFailuresPerMinute` | `5`    | 触发封禁前的失败次数阈值           |
| Failure store TTL      | 5 分钟 | `AnomalyFailures` 缓存生命周期窗口 |

**计为一次失败：** 处理器返回后，若最终状态码为 **`401`** 或 **`403`**，则对该 IP 的失败计数加一（缓存中为 8 字节
little-endian 计数器）。

**封禁行为：**

- 若请求开始时计数已 **≥ 5**，中间件立即返回 **`403 Forbidden`**，不执行处理器。
- 封禁响应在 `Next()` 之前返回，因此不会再次增加计数。
- 缓存条目 TTL 为自上次写入起 **5 分钟**；每次记录失败会刷新条目。过期后计数被清除。

除下方静态前端跳过列表外，所有路径均适用（包括已认证客户端）。处理器持续返回 401/403 时会触发封禁，与后续请求携带的凭证无关。

说明：常量名称含 “per minute”，实际存储窗口为 **5 分钟**；在条目过期前计数只会增加。

## 3. 匿名请求速率限制（按 IP）

基于 `golang.org/x/time/rate` 的令牌桶，每个 IP 一个限流器（`GlobalIPLimiter`）。

| 常量                   | 值    | 含义                                            |
|------------------------|-------|-------------------------------------------------|
| `MaxRequestsPerMinute` | `100` | 持续速率：每分钟 100 个令牌（约每 600 ms 一个） |
| `MaxRequestsBurst`     | `60`  | 突发容量（同时最多持有的令牌数）                |

- **受限对象：** 未通过认证校验的请求（见下）。
- **豁免对象：** 成功验证的 Session、Bearer 或 Basic，或可解析为有效会话 / bearer 的 GET/HEAD `?token=`。
- **超限时：** **`429 Too Many Requests`**。

### 豁免所需的认证

传递方式与生产认证一致（见 [authentication.md](./authentication.md)）：

| 传递方式                                          | 验证条件                        |
|---------------------------------------------------|---------------------------------|
| Cookie `renop_session` / `Authorization: Session` | 会话存在且未超过空闲超时        |
| `Authorization: Bearer <user>:<secret>`           | 用户名与 secret 匹配有效账户    |
| `Authorization: Bearer <upload-token>`            | 令牌已建立索引且未过期          |
| `Authorization: Basic …`                          | 用户名与密码 / secret 匹配      |
| GET/HEAD `?token=`                                | 令牌为有效会话 id 或上述 bearer |

无效凭证不提供豁免。此类请求仍会消耗限流令牌；若处理器返回 401/403，仍会增加失败计数。

空闲已过期的会话不视为已认证（空闲超时约为 7 天；详见认证文档）。

### 限流器生命周期

| 行为     | 说明                                 |
|----------|--------------------------------------|
| 键       | 客户端 IP 字符串                     |
| 空闲淘汰 | **5 分钟** 未使用的条目会被移除      |
| 定期清理 | 每 **5 分钟** 执行一次               |
| 紧急清理 | 已存储 IP 超过 **10,000** 时立即清理 |

## 静态前端跳过

仅对 **GET** 与 **HEAD**，下列路径跳过认证失败封禁与匿名限流；仍计入并发请求上限：

| 路径          |
|---------------|
| `/`           |
| `/index.html` |
| `/assets/*`   |
| `/js/*`       |
| `/css/*`      |
| `/svg/*`      |

API 路由、Maven 仓库路径及其他 HTTP 方法不会跳过。

## 状态码

| 码  | 条件                       |
|-----|----------------------------|
| 429 | 匿名 IP 超过令牌桶速率限制 |
| 403 | 401/403 过多导致 IP 被封禁 |
| 503 | 进程并发请求上限已满       |

响应正文通常为空。当前不返回 `Retry-After` 头。
