# 审核 API

审核 API 将所有权转让与消息中心分离。审核任务持久保存、支持分页，并且只能被决定一次。目前支持
Docker 映像、npm 软件包、Cargo crate、Maven 制品和 Maven 发布域。

## 适用范围与凭据

审核接口仅接受已经认证的浏览器会话。Basic 凭据和 Bearer API Token 均不能创建、列出、处理或取消审核
任务。用户也可以从账号菜单进入 `/account/reviews` 使用同一套流程。

待我审核视图仅包含当前账号在对应团队中具有 T3 或 T4 的任务。我的申请视图按照不可变账号标识返回
当前账号创建的任务，因此修改用户名不会丢失原有记录。

## 转让规则

申请人必须具有项目或发布域的有效 L4 所有权，或当前拥有存储库/系统管理权限。转让到超级团队时，申请人
还必须是目标团队成员。审核由该团队 T3/T4 管理员或系统管理员完成；申请人自身具备审核权限时也可以处理。

转让只修改所有权绑定，不会复制或删除包级成员。系统不接受两个团队之间的直接转让：应先将符合条件
的项目转回个人所有，再提交新的转入申请。

带命名空间的 Docker 映像和带作用域的 npm 软件包使用了团队的不可变前缀，因此不能转回个人所有。
来自镜像源的资源也不能转让。

## 查询任务

GET /api/reviews 返回有界分页结果。`view` 可为 `reviewer` 或 `requested`；`status` 可为 `pending`、
`approved`、`rejected`、`cancelled` 或 `all`。可选的 `types` 使用逗号分隔，支持五种资源类型。
`limit` 的范围是 1 至 100，`offset` 不得为负数。

响应包含 `tasks`、`total`、`limit`、`offset` 和最终使用的 `view`。每个任务保留来源与目标团队前缀、
申请人显示名称、时间、当前状态及已完成的决策信息。

## 提交转让

POST /api/reviews/super-team-transfers 接受 `resource_type`、`repository`、`resource_key` 和
`target_team_prefix`。Maven 发布域不传 `repository`；Maven 制品的资源键采用 `groupId:artifactId`。
目标团队为空表示申请转回个人所有。

同一资源同时只能有一项所有权转让处于待审核状态，与申请转入的目标无关。创建成功返回 `201 Created`、任务
正文及其 API 位置。

## 处理或取消

POST /api/reviews/{id}/decision 接受 `approved` 或 `rejected`。拒绝时必须提供非空理由，长度不超过
512 个字符；批准时会忽略附带理由。批准操作会重新检查当前绑定，并在同一数据库事务中完成转让与决策。

DELETE /api/reviews/{id} 仅允许申请人取消仍处于待审核状态的任务。并发处理使用待审核状态的比较并更新，
因此后续操作只会得到冲突响应，不能再次修改资源。

## 错误处理

失败响应通过 `X-Renop-Error-Code` 提供稳定错误码。`400` 表示筛选、资源标识或决策无效；`403` 表示
缺少所有权、目标团队成员资格或审核权限；`404` 表示任务不存在；`409` 表示已有相同申请、任务已经
完成、所有权已变化或该转让受到限制。

客户端应翻译已注册的错误码，不应直接显示响应正文。
