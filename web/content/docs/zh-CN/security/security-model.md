# 安全与权限

RenoP 综合凭据类型、API Token 能力、账号角色、存储库可见性及目标包/域团队进行授权。所属账号失去权限后，
任何凭据都不会继续保留该权限。

## 账号与系统角色

| 角色或权限                             | 效果                                                       |
|:---------------------------------------|:-----------------------------------------------------------|
| 匿名用户                               | 读取 `PUBLIC`，以及 `HIDDEN` 中精确已知的路径              |
| `base`                                 | 已认证账号，不隐式授予存储库写入                           |
| `canview:{repo}` / `canview:*`         | 读取指定或全部存储库，包括私有内容                         |
| `canmoderate:{repo}` / `canmoderate:*` | 审核指定或全部存储库中待处理的内容                         |
| `canupdate:{repo}` / `canupdate:*`     | 在包/域策略允许范围内向指定或全部存储库发布                |
| `showing`                              | 旧版兼容权限；允许在仓库目录中发现隐藏存储库               |
| `allview` / `proview`                  | 旧版全局私有读取别名                                       |
| `manager` / `admin`                    | 用户、存储库、设置、审计、更新及全部包团队的系统超级管理员 |

系统管理员权限全局有效。包团队 L0-L4 独立存在，仍是包/域协作的常规授权。管理员操作会被审计，不会静默创建
前端显示的团队成员。
版主权限允许查看私有审核内容，但不授予发布、用户管理、存储库配置或系统设置权限。

管理员和版主持有这些角色期间不可被封禁。封禁账号前，必须先撤销全部管理员和版主权限；已封禁的账号必须先解封，才能获得这些角色。数据库会在账号事务中检查两种操作，包括权限变更和重命名。冲突返回 `409` 和 `ACCOUNT_BAN_PROTECTED`；被拒绝的封禁不会撤销现有会话。

## 账号与 IP 封禁

系统管理员可以在用户页面填写原因、选择到期时间，并勾选“同时封禁已记录的登录 IP”。服务器从保留的会话记录（最近活跃的 64 条）和过去 30 天最近 256 次成功登录中收集最多 64 个规范化地址，并保留当前有效 IP 封禁已包含的地址。不接受浏览器任意指定地址。没有可用地址时，整个操作返回 `409 ACCOUNT_BAN_IP_UNKNOWN`；取消勾选即可仅封禁账号。

IP 限制、账号封禁和会话撤销在同一事务中提交。限制在重启、账号改名后仍然有效，并随账号封禁一起到期。启动时会保留已注销账号的永久占位记录，不会重新创建凭据或成员关系。取消勾选会移除此账号的 IP 限制，但保留账号封禁；解封则移除两者。若另一个账号的有效封禁仍覆盖同一地址，该地址会继续被阻止。编辑时省略 `ban_ip` 会保留当前有效的 IP 限制。

被封禁的地址发起 HTTP 请求时收到 `403` 和 `IP_BANNED`，包括登录、注册、已认证请求和公开下载。共用该地址的其他用户同样受到影响。只有配置为受信任代理的来源才可提供转发客户端地址。管理员状态响应只提供地址数量，不返回保存的地址；所有封禁接口均要求系统管理员权限，返回私有且不可缓存的元数据。API 令牌还必须具有 `admin:users` 范围。

| 方法 | 路径 | 请求或结果 |
|---|---|---|
| GET | `/api/tokens/:name/ban` | `{ban,ip_count,protected_role}` |
| PUT | `/api/tokens/:name/ban` | `{reason,expires_at,ban_ip}`；到期时间可为 null |
| DELETE | `/api/tokens/:name/ban` | 解除账号及其 IP 限制；`204` |

## 存储库与团队层级

- 存储库可见性定义发现与基础读取边界：`PUBLIC`、按权限发现的 `HIDDEN`、要求授权的 `PRIVATE`；
- 存储库权限不会自动创建 npm/Cargo/Docker 包，也不会自动验证 Maven 域；
- npm/Cargo/Docker 团队使用 L0 读取、L1 发布、L2 生命周期/元数据、L3 成员管理、L4 所有权；
- Maven 团队归属于已验证全局域，并在全部 Maven 存储库中生效；
- 私有 Docker 镜像不隐式授予公开 L0，Blob 访问限制在用户有权读取的镜像中。
- 私有 npm 软件包必须使用作用域，并要求明确的软件包成员或管理员权限。

## 凭据传输方式

- **浏览器会话**：HttpOnly `renop_session` Cookie，用于私有安全设置与 Token 管理；
- **Basic**：用户名加密码或 API Token，仅用于标准包协议；
- **Bearer API Token**：用于 API 与包自动化的能力及精确目标策略；
- **Docker Bearer**：仅包含来源凭据与镜像共同允许动作的短期 Token。

`Authorization: Session`、URL 中的会话密钥与查询参数凭据均被拒绝。API Token 权限与目标始终和账号当前授权
取交集。

恢复会话时收到 `403` 不会使浏览器退出登录：有效会话仍可能受到 IP 或授权限制。收到 `401` 才需要重新登录。

## 纵深防御

- 密码与恢复代码使用加盐单向校验，API Token 明文不持久化；
- 会话具有闲置过期与按设备撤销，账号恢复会原子撤销已有会话；
- 速率限制、渐进 IP 封禁、活跃请求上限与可信代理校验保护网络边界；
- 上传、归档解包、镜像与更新包使用有界流式处理、路径校验、哈希与临时存储；
- 行为日志与持久消息记录安全结果；产品策略要求中性通知时不会披露执行者身份。
