# 权限与安全模型

RenoP 采用基于角色的访问控制（RBAC）与细粒度仓库权限相结合的安全模型。

## 1. 用户角色体系

| 角色                     | 权限范围                   | 说明                                           |
|:-------------------------|:---------------------------|:-----------------------------------------------|
| **匿名访问 (Anonymous)** | 仅限 PUBLIC 仓库读取       | 未携带任何凭据的访问者                         |
| **普通用户 (User)**      | 依据绑定的仓库权限执行读写 | 经过登录认证的标准用户                         |
| **管理者 (Manager)**     | 管理大部分配置与用户       | 具备用户管理、令牌管理与仓库配置修改权限       |
| **超级管理员 (Admin)**   | 拥有系统全部最高控制权     | 包含系统级底层设置、更新器与全部仓库的绝对控制 |

## 2. 仓库级细粒度权限

对于普通用户，可以通过权限字符串精确控制其对特定仓库的操作范围：

| 权限字符串         | 权限描述                           |
|:-------------------|:-----------------------------------|
| `canview:{repo}`   | 允许查看与拉取指定仓库中的制品     |
| `canupdate:{repo}` | 允许向指定仓库上传、部署与修改制品 |
| `canadmin:{repo}`  | 允许对指定仓库进行管理操作         |
| `allview`          | 允许查看所有私有仓库（全局只读）   |
| `allupdate`        | 允许向所有仓库上传部署（全局写入） |

## 3. 认证方式与凭据传递

RenoP 支持以下多种认证方式：

1. **Cookie 会话**：在 Web 管理控制台登录后，浏览器会自动携带 `renop_session` Cookie。
2. **HTTP Basic Auth**：标准用户名 + 密码，或用户名 + 个人访问令牌（PAT），常用于 Maven `settings.xml`、Gradle 或 Docker CLI。
3. **Bearer Token**：在请求头中携带 `Authorization: Bearer <token>`，适用于 CI/CD 自动化流水线。
4. **URL 查询参数（仅限 GET/HEAD）**：可在临时下载链接中附带 `?token=...`。

## 4. 会话管理与安全策略

- **会话有效期**：登录会话在连续 7 天无活动后自动过期；有活动时会自动滑动续期。
- **密码哈希**：用户密码采用现代哈希算法加盐存储，不保存明文。
- **登录防爆破**：连续认证失败的 IP 会触发阶梯式封禁策略。
