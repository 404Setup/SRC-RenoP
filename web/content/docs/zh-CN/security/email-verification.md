# 安全邮箱验证

## 修改邮箱

在 **账号安全**中修改私有邮箱。启用邮件服务时，保存操作会向新地址发送验证邮件。输入八位验证码后，修改才会生效；验证成功前，原邮箱仍可使用。未启用邮件服务时，保存操作直接更新邮箱。

两种方式均遵循已配置的邮箱黑名单或白名单，邮件服务关闭时也不例外。规则支持完整邮箱、精确提供商 @domain 和包含子域名的后缀
.suffix。黑名单模式还可启用内置临时邮箱名单；白名单模式忽略该名单。同一国际化域名的 Unicode 与 Punycode
写法会匹配同一规则。已被其他账号使用，或仍由已注销账号保留的地址不能被占用。

## 登录邮箱别名

主邮箱和其他邮箱共用唯一的账号归属记录。如果第三方身份或其返回的任意联系邮箱属于其他账号，包括注销保留期内的地址，绑定会失败。绑定、邮箱占用和账号安全变更在同一事务中提交；失败不会改变现有账号。系统不会根据邮箱合并账号。

“其他登录邮箱”列出私有的辅助地址，可用于同一账号的密码或 Passkey 登录、邮件密码重置及离线恢复码验证，原有密码和二次验证策略仍然生效。通知继续发往主邮箱。每个账号最多保留
128 个地址，包含主邮箱。

第三方必须验证其返回的地址，或者该地址已经归当前登录账号所有。否则，请先在第三方验证，或使用“添加并验证邮箱”后再绑定。添加地址要求启用
RenoP 邮件服务，并使用现有验证码对话框。第三方注册若返回未验证邮箱，必须验证该地址；验证另一个地址不能替代。GitHub 的
no-reply 地址不在导入范围内。

解除第三方绑定不会删除其邮箱别名。移除别名会释放该地址；之后重新进行第三方授权时，地址可能再次加入。主邮箱不能通过别名移除操作删除。封禁保留全部地址；注销后全部地址占用
14 天，即使账号没有主邮箱。管理员提前释放会作用于整个保留地址集合。

| 方法   | 路径                            | 请求或响应                                                          |
|--------|---------------------------------|---------------------------------------------------------------------|
| GET    | `/api/auth/profile/security`    | 在 `email` 之外返回 `email_aliases`                                 |
| PUT    | `/api/auth/profile/email`       | `{"email":"alias@example.com","alias":true}`；返回 `202` 和验证回执 |
| DELETE | `/api/auth/profile/email/alias` | `{"email":"alias@example.com"}`；返回更新后的账号安全信息           |

别名确认使用现有确认接口；验证用途保存在挑战中，不能通过确认请求更改。移除别名要求浏览器在最近五分钟内完成登录。相关错误以
`409` 返回 `ACCOUNT_EMAIL_PROOF_REQUIRED`、`ACCOUNT_EMAIL_LIMIT` 或 `ACCOUNT_EMAIL_PRIMARY`；移除时会话过旧返回
`MFA_REAUTH_REQUIRED`。

升级会补全已有主邮箱的归属记录。旧版本没有保存第三方邮箱，因此已有绑定会在下次授权时取得别名。签发新浏览器会话前，持久化层会在账号事务中重查封禁和账号到期状态。

## 验证 API

以下操作需要当前浏览器 Cookie。JSON 请求体要求 `Content-Type: application/json`，上限为 4,096 字节。

| 方法 | 路径                              | 请求或响应                                                                                             |
|------|-----------------------------------|--------------------------------------------------------------------------------------------------------|
| GET  | `/api/auth/profile/security`      | 包含 `email` 和 `email_verification_required`                                                          |
| PUT  | `/api/auth/profile/email`         | `{"email":"new@example.com"}`；入队后返回 `202` 和 `{id,status,ticket}`，否则返回 `200` 和账号安全状态 |
| POST | `/api/auth/profile/email/confirm` | 邮箱和验证码；返回 `200` 和更新后的账号安全状态                                                        |
| GET  | `/api/auth/mail/:id`              | 邮件状态；通过发起请求的账号或 `X-Renop-Mail-Ticket` 授权访问                                          |

```json
{"email": "new@example.com", "code": "01234567"}
```

验证码有效期为 10 分钟，允许五次错误尝试，并绑定发起请求的浏览器会话。60 秒后可以申请新验证码，但仍受 IP
发件限速约束。新邮件成功入队后，旧验证码失效；入队失败会保留旧验证码。验证码、邮件队列和 IP 限速计数在同一事务中提交。

验证码错误、过期、已使用或对应状态已变化时，返回 `400` 和 `ACCOUNT_EMAIL_CODE_INVALID`，浏览器保持登录。地址已被占用时返回
`409` 和 `ACCOUNT_EMAIL_CONFLICT`。名单策略拒绝地址时返回 `400` 和 `mail_recipient_blocked`
。已撤销的会话不能确认修改；账号凭据或安全设置变化也会使待处理验证失效。

## GitHub 验证

配置 GitHub 登录后，可选择 **使用 GitHub 已验证邮箱**，通过 `GET /api/auth/github/start?intent=email` 授权重新获取邮箱。该流程请求
`user:email`
权限，并读取 [GitHub 当前用户的邮箱列表](https://docs.github.com/en/rest/users/emails#list-email-addresses-for-the-authenticated-user)。

RenoP 优先选择已验证的主要联系邮箱；没有主要地址时，选择第一个已验证的联系邮箱，排除 GitHub 的 no-reply
地址。获取的地址通过本地名单检查后保存。此方式无需配置邮件发送账号，也不会建立或替换 GitHub 登录绑定。

回调只能使用一次，有效期为 10 分钟，必须由原账号、原浏览器会话返回，且账号凭据未发生变化。第三方访问令牌仅用于本次查询，不会保留。

## 运行说明

RenoP 最多保留 2,048 条待处理邮箱修改记录。新增记录前和邮件清理任务中会删除过期记录。验证码以带密钥的哈希保存；队列中的邮件内容使用私有邮件加密密钥加密。验证码和邮件查询凭据不会进入
URL、日志或浏览器存储。

修改成功后会记录个人资料变更活动。串行邮件工作线程按照场景路由和发件限制发送 `email_changed`
通知。入队成功并不等于投递成功；验证界面会显示服务商的投递进度和失败状态。

其他服务也可在资料编辑页提供[使用已验证邮箱](./oauth-login.md)。此操作同样要求重新授权，保留当前登录绑定，并遵守收件人策略。没有明确邮箱验证声明的地址，必须改用
RenoP 邮箱验证码验证。

## 账号语言

登录时会在每台设备上恢复账号保存的语言。尚未保存偏好的账号会采用当前界面语言，之后在语言选择器中的修改会自动保存。注册时，页面语言会与新账号一起保存。保存失败时，设备会保留一项待发送选择，在恢复连接、返回页面或刷新后重试。旧账号的待发送选择不会应用到其他账号。

语言偏好属于私密信息，在修改用户名和重启后保留，注销账号时清除。修改语言不会变更凭据，也不会使正在进行的第二步验证失效。后台通知和密码重置邮件使用收件账号的偏好，通过邮箱别名识别账号时同样适用。尚未保存偏好的收件人使用发起页面的
`Accept-Language`，缺省为 `en-US`。已入队邮件保留入队时选定的语言。

支持的标识为 `en-US`、`zh-CN`、`zh-HK`、`zh-TW`、`zh-YUE`、`ko-KR`、`ja-JP`、`de-DE`、`fr-FR`、`ru-RU`、`es-ES` 和 `pt-PT`。

| 方法 | 路径                       | 请求或响应                                                                                  |
|------|----------------------------|---------------------------------------------------------------------------------------------|
| GET  | `/api/auth/profile/locale` | `{"user_id":"00000000-0000-4000-8000-000000000001","locale":"fr-FR"}`；空值表示尚未保存偏好 |
| PUT  | `/api/auth/profile/locale` | `{"user_id":"00000000-0000-4000-8000-000000000001","locale":"fr-FR"}`；返回保存后的规范标识 |

两个操作均要求当前浏览器 Cookie，偏好数据响应带有 `Cache-Control: no-store`。API 令牌不能读取或修改此偏好。不支持的值返回
`400` 和 `ACCOUNT_LOCALE_INVALID`。[邮件配置](../configuration/mail.md) 不再提供全局语言选择器。

PUT 必须回传 GET 返回的不可变 `user_id`，账号不匹配时返回 `403`。设备上的待发送选择也绑定到此
ID，因此修改用户名或后续重复使用用户名不会在账号之间转移语言偏好。
