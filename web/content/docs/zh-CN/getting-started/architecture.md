# 系统架构

本文档简要介绍 RenoP 的内部架构设计与请求处理流程。

## 1. 架构模块划分

RenoP 内部由以下核心模块组成：

```
+-------------------------------------------------------------------+
|                        Web 前端管理界面                            |
|             (单页应用，内嵌于二进制中，支持多语言与暗色主题)       |
+-------------------------------------------------------------------+
                                  │
                                  ▼
+-------------------------------------------------------------------+
|                         HTTP 服务路由层                           |
|        - 安全与防异常探测中间件 (Anomaly & Rate Limiting)          |
|        - 统一认证中间件 (Cookie Session / Bearer / Basic)         |
|        - 数据序列化 (JSON / Protobuf 双格式支持)                   |
+-------------------------------------------------------------------+
                                  │
                                  ▼
+-------------------------------------------------------------------+
|                         业务服务领域层                            |
|  - Maven 服务 (标准布局读写, Javadoc 解压浏览, GPG 签名校验)      |
|  - Cargo 服务 (稀疏索引, Crate 发布/下载, Cargodoc 在线文档)      |
|  - Docker 服务 (OCI v2 规范, 分块 Blob 上传, 跨仓库 Blob 挂载)     |
|  - 管理与消息服务 (用户与令牌管理, 系统设置, 消息中心, 自动更新)  |
+-------------------------------------------------------------------+
                                  │
                 ┌────────────────┴────────────────┐
                 ▼                                 ▼
+---------------------------------+  +-------------------------------+
|           数据库抽象层          |  |           存储适配层          |
| - SQLite (内嵌默认)             |  | - 本地文件系统 (原子写入与缓存)|
| - MySQL 8.0+                    |  | - S3 兼容对象存储 (MinIO/R2)  |
| - PostgreSQL (基于 pgx/v5 驱动) |  | - GPG 签名隔离队列            |
+---------------------------------+  +-------------------------------+
```

## 2. 请求处理机制

### 流式数据传输

在处理大文件上传与下载时（如大型 JAR 包、Crate 压缩包或 Docker 镜像分块）：

- 数据流直接在网络连接与存储后端（磁盘文件或 S3）之间流动，避免将完整大文件一次性缓存在内存中。
- 底层复用 Byte Buffer 池，减少内存分配开销。

### 统一数据库抽象

RenoP 支持 SQLite、MySQL 与 PostgreSQL：

- 所有用户凭证、访问令牌、审计日志与消息中心数据均持久化在配置的数据库中。
- 采用参数化查询，并针对 PostgreSQL 实现参数占位符自动重绑定。

### 存储一致性与临时文件隔离

- **本地写入**：先写入 `.tmp` 临时文件并计算校验和，写入成功后通过重命名替换目标文件，防止传输中断产生损坏文件。
- **GPG 隔离队列**：在启用了 GPG 强制校验的仓库中，未经过签名的制品暂存在 `.renop.tmp.gpg` 隔离队列中，直到签名验证通过才正式公开。
