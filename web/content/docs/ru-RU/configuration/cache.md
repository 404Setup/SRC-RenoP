# Режимы кэширования

По умолчанию RenoP использует память. Администратор может выбрать Redis или Valkey в настройках службы.
Изменение режима вступает в силу после перезапуска.

## Настройка

```yaml
cache:
  mode: memory
  address: localhost:6379
  username: ""
  password: ""
  database: 0
  tls: false
  timeout_ms: 1000
```

`mode` принимает `memory`, `redis` или `valkey`. Для `address` используйте `host:port`; IPv6 заключается в скобки.
Имя пользователя необязательно. Поддерживаются пароль и TLS с проверкой сертификата сервера.
Номер базы должен находиться в диапазоне 0–65535 и существовать на выбранном сервере.
`timeout_ms` задаёт 10–10000 миллисекунд для подключения, ожидания пула, чтения и записи.
Пул ограничен восемью соединениями. При внешнем режиме сервер кэша должен быть доступен во время запуска.

## Кэшируемые данные

Режим применяется к содержимому метаданных артефактов, разобранным метаданным Maven, результатам аутентификации,
запросам аккаунтов, сессий, профилей и идентификаторов, политикам кэша репозиториев, токенам Docker
вышестоящих реестров и ресурсам SPA. Сгенерированный HTML также использует выбранный режим.
Постоянное хранилище, активные сессии, блокировки, соединения и рабочие процессы сохраняют прежнее управление.

Внешние значения шифруются и проверяются ключом, уникальным для процесса. Непрозрачные ключи кэша не содержат
учётных данных или путей запросов. Локальные индексы хранят поля для ограниченного вытеснения и адресного отзыва.
Отзыв удаляет ссылки даже при неудачном удалении на сервере. Результат аутентификации, начатой до отзыва,
не может снова заполнить кэш.

Сохраняются прежние ограничения ёмкости и логического срока действия. Ёмкость файлов определяется
`server.file_cache_size_mb`. Внешнее значение ограничено 2 МиБ и хранится не более 24 часов;
файлы, политики и ресурсы SPA истекают через час. Настройте общий лимит памяти и политику вытеснения
на сервере кэша. RenoP не меняет настройки общего сервера.

Перезапуск кэша, вытеснение, отсутствие записи, неверный шифротекст или ошибка подключения во время работы
вызывают обращение к базе, хранилищу или генератору. После сетевой ошибки кэш обходится пять секунд.
Перезапуск RenoP создаёт новое пространство имён и ключ; старые значения удаляются по сроку действия.
Кэш не является источником авторитетных данных.

## API администрирования

```http
GET /api/settings/cache
PUT /api/settings/cache
POST /api/settings/cache/test
```

Нужен системный администратор или разрешённый токен с `admin:settings`.
GET и PUT не возвращают сохранённый пароль. `password_configured` указывает его наличие;
`restart_required: true` означает необходимость перезапуска. Пустой пароль сохраняет прежнее значение,
а `clear_password: true` удаляет его.

PUT принимает поля из примера. Проверка использует те же параметры, сохраняет пропущенный пароль
и проверяет соединение без записи настроек. Размер тела ограничен 8 КиБ.
Стабильные ошибки: `cache_settings_invalid`, `cache_settings_save_failed` и `cache_connection_failed`.

Аккаунту нужны PING, SET, GETRANGE и DEL для `renop:*`, а также необходимые серверу команды
аутентификации и выбора базы. Эти endpoints не настраивают Sentinel или обнаружение кластера.
