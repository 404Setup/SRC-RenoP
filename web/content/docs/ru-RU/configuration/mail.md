# Отправка почты

В разделе **Настройки → Сервис** добавьте почтовый аккаунт, выберите предустановку, укажите учётные данные и сохраните
настройки.
Задайте публичный HTTPS-адрес экземпляра и включите почту. Изменения применяются к следующим операциям очереди без
перезапуска.

## Конфигурация

```yaml
mail:
  enabled: false
  public_url: https://packages.example.com
  site_name: RenoP
  template_style: card
  delay: {value: 5, unit: second}
  manual_rate: {limit: 1, interval: {value: 2, unit: minute}}
  account_rate: {limit: 50, interval: {value: 1, unit: minute}}
  calibration: {value: 5, unit: minute}
  list_mode: blacklist
  use_disposable_blacklist: false
  addresses: []
  accounts:
    - id: primary
      name: Main mailbox
      enabled: true
      provider: smtp
      preset: smtp-custom
      scenes: ["*"]
      from: noreply@example.com
      from_name: RenoP
      smtp_host: smtp.example.com
      smtp_port: 587
      smtp_security: starttls
      username: noreply@example.com
      password: ""
      quota: {limit: 0, period: month}
      force_send: false
      overage: {limit: -1, period: month}
      balance_micros: null
      fetch_balance: false
      pricing:
        currency: USD
        rounding: proportional
        tiers:
          - {up_to: 0, amount_micros: 100000, batch_size: 1000}
```

Один активный аккаунт обслуживает все сценарии. При нескольких аккаунтах явное назначение имеет приоритет над
единственным резервным аккаунтом `*`.
Один сценарий нельзя назначить двум активным аккаунтам. Если назначения нет, отправитель не выбирается автоматически.
Поле `id` постоянно: изменение отображаемого имени сохраняет счётчики. Неотправленные письма удалённого аккаунта
отменяются при следующей обработке.
Отключение почты или аккаунта приостанавливает отправку, но не продлевает срок действия писем.

`delay` принимает секунды, минуты или часы. Ноль убирает задержку, сохраняя последовательную отправку.
`manual_rate` ограничивает ручные запросы с одного IP, включая тестовые письма; период задаётся в минутах, часах или
днях.
`account_rate` учитывает ручные и автоматические попытки одного отправителя; для периода также доступны секунды.
Лимиты и длительности должны быть положительными. По умолчанию разрешён один ручной запрос с IP за две минуты и 50
попыток с аккаунта в минуту.

`list_mode` принимает `blacklist` или `whitelist`. Политика проверяется до постановки в очередь и непосредственно перед
отправкой. Unicode и Punycode для одного международного домена совпадают; завершающая точка домена игнорируется.

| Правило                   | Совпадение                                            |
|---------------------------|-------------------------------------------------------|
| `person@example.com`      | Полный адрес                                          |
| `@example.com`            | Точный домен провайдера без поддоменов                |
| `.com` или `.example.com` | Полный суффикс DNS, включая базовый домен и поддомены |

Параметр `use_disposable_blacklist: true` дополняет чёрный список встроенным списком временной почты. По умолчанию
выключен и игнорируется в режиме белого списка. Снимок объединяет 75 627 доменов
из [disposable/disposable-email-domains](https://github.com/disposable/disposable-email-domains)
и [disposable-email-domains/disposable-email-domains](https://github.com/disposable-email-domains/disposable-email-domains)
без ограничений по стране или владельцу. Блокируются включённые домены и их поддомены; сетевые запросы не выполняются.

Это снимок, поставляемый с выпуском, а не исчерпывающий перечень всех новых провайдеров. Его можно дополнить
собственными правилами. Сборка автоматически создаёт игнорируемый каталог `internal/mail/data/` по ревизиям и
контрольным суммам из `scripts/update-disposable-domains.ps1`; проверенные локальные данные используются повторно без
сети. Лицензии приведены в `THIRD_PARTY_NOTICES.md`.

## Провайдеры и адреса сервисов

|---------------------------|--------------------------------------------------------------------------------------------------------|----------------------------------------------------------------|
| SMTP                      | Открытый SMTP, неявный SSL/TLS или обязательный STARTTLS; пароль либо поддерживаемый OAuth             | Локальные оценки и ответ о принятии SMTP                       |
| Cloudflare Email          | ID аккаунта и API-токен, глобальный REST-адрес                                                         | Первичный результат доставки, отказа или очереди               |

| Amazon SES                | Региональные IPv4, двухстековые и доступные FIPS-адреса; ключ, секрет и необязательный временный токен | Квота отправки и сведения о сообщении                          |
| Twilio SendGrid           | Глобальный и европейский сервисы, API-ключ                                                             | Кредиты и статус Email Activity                                |
| Google Gmail              | Gmail и Workspace, делегированный OAuth                                                                | Метка отправленного сообщения                                  |
| Alibaba Cloud Direct Mail | Ханчжоу, Сингапур, Вирджиния и Франкфурт; публичные и VPC-адреса; ключ и секрет                        | Бесплатная квота, баланс, статистика без точного сопоставления |

| Feishu / Lark Mail        | Сервисы Feishu и Lark, делегированный пользовательский OAuth                                           | Доставка получателю                                            |

Доступность регионов определяется каталогами [SES](https://docs.aws.amazon.com/general/latest/gr/ses.html)
и [Direct Mail](https://www.alibabacloud.com/help/en/direct-mail/api-dm-2015-11-23-endpoint).
VPC-адреса Direct Mail требуют подключения внутри соответствующего региона. Выведенные из эксплуатации адреса Сиднея
исключены.
SMTP-предустановки включают Gmail, Outlook.com, Microsoft 365, QQ, NetEase 163/126, Cloudflare, SendGrid, SES, Direct
Mail, Tencent и Feishu.
Адреса и цены редактируются. Смена предустановки загружает её значения; смена провайдера не переносит сохранённые
секреты прежнего провайдера.

Ручные квоты и дополнительные лимиты сохраняются. Смена валюты предустановки очищает ручной баланс, не переопределяя
денежные единицы прежней суммы.

## Учётные данные и права

Точные области, действия IAM/CAM/RAM, настройка токенов, условия провайдеров и проверенные контракты описаны
в [Разрешениях почтовых API](mail-api-permissions.md).
Обычным аккаунтам Tencent API нужен утверждённый шаблон в `tencent_template_id`; произвольное содержимое `Simple` —
старая ограниченная возможность.

`smtp_security` принимает `plain`, `tls` или `starttls`. Порт по умолчанию — 465 для неявного TLS и 587 в остальных
случаях.
TLS проверяет сертификат и имя сервера. Выбранный STARTTLS обязателен; открытый SMTP необходимо выбрать явно.
При необходимости используйте пароль приложения. OAuth SMTP поддерживает токены обновления Gmail и Microsoft; одиночный
токен доступа обновляет администратор.

Делегированный Graph использует `client_id`, необязательный `client_secret` и `refresh_token`. Для личных аккаунтов
подходит тенант `common`.
Доступ приложения требует ID тенанта Entra и учётных данных клиента; в `mailbox` укажите ID или адрес пользователя. При
делегировании допустимо `me`.
Для отправки требуется `Mail.Send`, для поиска в отправленных — соответствующее право `Mail.Read`. Права приложения
требуют согласия администратора.
См. [Graph sendMail](https://learn.microsoft.com/en-us/graph/api/user-sendmail)
и [национальные облака](https://learn.microsoft.com/en-us/graph/deployments).

Gmail требует делегированных прав отправки и чтения метаданных. Feishu/Lark требует пользовательского токена и прав
отправки и чтения сообщений.
RenoP обновляет OAuth-токены последовательно и сохраняет заменённые токены обновления перед отправкой.
Поля API: `api_key`, `api_secret`, необязательный `session_token`, `account_id`, `region`, `endpoint` и необязательный
`billing_endpoint`.
Провайдер должен разрешать адрес отправителя. ID аккаунта, ID почтового ящика и API-ключ не взаимозаменяемы.

## Квоты и тарификация

`quota.limit` задаёт локальную квоту: отрицательное значение снимает ограничение, ноль или отсутствие включает
автоматическое получение, положительное задаёт ручную квоту.
При отсутствии удалённых данных автоматический режим изначально не ограничен. Ошибка сверки сохраняет известные
ограничения, не добавляя кредитов.
Ручные периоды — календарные часы, дни, недели с понедельника и месяцы по UTC. Использование хранится отдельно для всех
четырёх периодов.

`force_send` разрешает дополнительную квоту после исчерпания обычной.
Отрицательный `overage.limit` снимает дополнительный лимит, ноль запрещает превышение. Период принимает `hour`, `day`,
`week` или `month`.
Жёсткие ограничения провайдера сохраняются: технический лимит SES нельзя обойти оплатой превышения.
Если API квоты нет, вручную укажите объём, включённый в приобретённый план.

Границы суммарного объёма `up_to` в `pricing.tiers` должны возрастать. Только последняя граница может быть нулём,
обозначая отсутствие верхнего предела.
Ступень тарифа задаёт `amount_micros` за `batch_size` писем. Для оплаты каждого письма размер пакета равен одному.
`rounding: proportional` пропорционально распределяет цену; `batch` списывает цену всего пакета при первом письме.
Цены и баланс выражаются в миллионных долях трёхбуквенной валюты `currency`: 1000000 означает одну денежную единицу.
Интерфейс показывает обычные суммы.

Дата проверки предустановок —
2026-09-08: [Cloudflare](https://developers.cloudflare.com/email-service/platform/pricing/) — 0,35 USD за 1000
дополнительных писем; [SES](https://aws.amazon.com/ses/pricing/) — 0,10 USD за 1000 исходящих.
[Опубликованные тарифы SendGrid](https://sendgrid.com/content/dam/sendgrid/global/en/other/sendgrid-pricing/twi121--sendgrid-pricing-pdf-st1.pdf)
задают редактируемые значения Essentials 50K и Pro 100K; европейская отправка требует подходящего плана.
[Direct Mail](https://www.alibabacloud.com/help/en/direct-mail/billing-methods) — 0,29 USD за
1000; [Tencent China](https://cloud.tencent.com/document/product/1288/47930) — 0,0019 CNY за
письмо, [международный Tencent](https://www-sg.tencentcloud.com/document/product/1084/39335) — 0,00028 USD за письмо.
Предельная стоимость в предустановках Graph, Gmail и Feishu/Lark равна нулю, но ограничения планов действуют.
Оценки не включают подписки, налоги, трафик вложений и дополнительные услуги. Приведите модель в соответствие со своим
договором.

Пустой `balance_micros` означает неизвестный баланс. Нулевой, отрицательный или недостаточный для следующего превышения
известный баланс приостанавливает отправку.
`fetch_balance` включает поддерживаемую сверку баланса в заданной валюте. Недоступные данные не превращаются в нулевой
баланс.
Квота и стоимость превышения резервируются до отправки. Неверные учётные данные, настройки отправителя и сбой соединения
до передачи запроса не расходуют квоту.
Другие попытки, включая отказ получателя и неопределённый результат, учитываются. Явно неоплачиваемый сбой возвращает
квоту один раз; лимит попыток остаётся списанным.
Поздняя проверка не добавляет удалённые кредиты повторно, если более новая сверка уже учла корректировку провайдера.

`calibration` по умолчанию равен пяти минутам; доступны минуты, часы и дни. Пустое, нулевое или отрицательное значение
отключает запросы квоты и баланса.
Между сверками RenoP ведёт локальный учёт. При включённой сверке первый запрос предшествует первой отправке аккаунта.
Для провайдеров без публичного API квоты или баланса используются локальные оценки и ручная настройка.

## Очередь и статус доставки

Отправка, обновление OAuth, сверка и проверка статуса выполняются одним последовательным обработчиком. По умолчанию
после завершённой попытки выдерживается пять секунд.
Очередь и счётчики переживают перезапуск. Аренда в базе предотвращает одновременную отправку несколькими обработчиками.
Прерванная до сохранения результата отправка становится `unknown` и автоматически не повторяется.

`accepted` означает принятие запроса провайдером; `sent` — успешную проверку папки или состояния отправленного
сообщения.
`delivered` требует явного результата доставки. Очередь, пауза, проверка, ошибка, истечение срока, отмена и неизвестный
результат различаются.
Проверки SES и SendGrid требуют соответствующих функций и прав. Отправленное состояние Graph и Gmail не доказывает
получение адресатом.
Feishu/Lark использует API `send_status` для каждого получателя, различая доставку, отклонение и ожидание обработки.
Публичная статистика Direct Mail не содержит ID писем: RenoP запрашивает её, но возвращает `unknown`, не приписывая
результат другого письма.
Cloudflare предоставляет первичный результат непосредственно; неподдерживаемый API проверки отдельного письма не
вызывается.

После отправки проверки выполняются с ограниченным увеличением задержки. Повторные ошибки или истечение срока дают
неизвестный результат и запись глобального журнала.
Коды ошибок провайдера сохраняются в административных журналах. Публичный статус скрывает получателя, содержимое,
секреты и необработанную диагностику.

## Шаблоны и уведомления

`template_style` выбирает `card`, `compact` или `notice`. Шаблоны используют нейтральные поверхности, скруглённые
карточки, кнопки-капсулы и светлую/тёмную палитру сервиса. Письма используют сохранённый язык учётной записи получателя;
для новых регистраций и получателей без предпочтения берётся `Accept-Language` исходной страницы с запасным значением
`en-US`. Поддерживаются все 12 языков интерфейса. Язык фиксируется при постановке письма в очередь. Старый глобальный
параметр `locale` игнорируется и больше не отображается в настройках.
Все стили содержат обычный текст, экранированные подстановки и HTTPS-ссылки только на настроенный экземпляр.

```text
registration_verify, registration_success, password_reset, password_changed,
email_verify, email_changed, quota_changed, review_status, review_requested,
permission_changed, account_banned, account_unbanned, collaboration_invitation,
super_team_invitation, pending_reviews, unusual_login, security_changed,
account_retired, notification, test
```

Изменения пароля и Passkey, прав, блокировки, пользовательских квот, проверки, приглашения и внутренние сообщения
используют постоянные события.
Уведомления дедуплицируются; первое включение почты не воспроизводит старую историю действий.
Сигнал новой сети сравнивает IPv4 /24 либо IPv6 /56 с предыдущим входом; это изменение сети, а не определение
географического местоположения.
Перед отправкой связанных с аккаунтом писем проверяются его актуальность и адрес безопасности. Закрытие аккаунта удаляет
его письма из очереди.

## API администрирования

```http
GET /api/settings/mail
PUT /api/settings/mail
GET /api/settings/mail/presets
POST /api/settings/mail/test
GET /api/settings/mail/accounts/:id
GET /api/settings/mail/jobs?limit=20&offset=0&status=failed
GET /api/settings/mail/templates/:scene?style=card
GET /api/auth/mail/:id
```

Интерфейсы настроек требуют административных прав. JSON заменяет всю почтовую конфигурацию; размер запроса ограничен 1
MiB.
GET и успешный PUT скрывают секреты и возвращают `secrets_configured` — соответствие ID аккаунтов именам заполненных
полей.
Для прежнего провайдера пустая строка сохраняет секрет. `clear_secrets: {"primary":["password"]}` удаляет его явно.
Семь полей только для записи: `password`, `api_key`, `api_secret`, `session_token`, `client_secret`, `access_token`,
`refresh_token`.
Постоянный ключ шифрования через этот API не принимается и не возвращается.

Тестовая отправка использует сохранённые настройки и принимает следующий JSON:

```json
{"account_id": "primary", "to": "receiver@example.com"}
```

Успешная постановка в очередь возвращает HTTP 202, не подтверждая доставку:

```json
{"id": "opaque-job-id", "status": "queued", "ticket": "private-status-capability"}
```

Запрашивайте статус с полученным заголовком `X-Renop-Mail-Ticket` либо с сеансом владельца.
Храните билет в тайне и не помещайте в URL. Неверный владелец или билет дают 404, недоступное хранилище — 503.
Состояние аккаунта включает расход по периодам, попытки, оценку остатка квоты, баланс, дополнительные расходы и
последнюю сверку.
Список принимает `limit` 1–50, `offset` 0–10000 и необязательный точный фильтр `status`. Предпросмотр возвращает тему,
HTML и текст.

Для SMTP сохранённые секреты сохраняются только при неизменных сервере и имени пользователя.

## Хранение и ограничения

Максимум: 64 аккаунта, 1000 записей получателей и 20 ступеней тарифа на аккаунт.
Периоды ограничены одним годом, квоты и объёмы ступеней — миллиардом писем.
Текст вместе с HTML и каждый ответ провайдера ограничены 128 KiB. У задания один получатель и срок до 24 часов.
Очередь допускает 2048 активных заданий и 12048 записей всего. Очистка сокращает завершённую историю примерно до 8000
строк и удаляет записи старше семи дней.
IP-счётчики истекают, а состояние удалённого отправителя очищается через 24 часа.

Содержимое и обновляемые токены шифруются постоянным `mail.encryption_key` из закрытого файла настроек.
Сохраняйте резервную копию ключа вместе с базой. Потеря или замена ключа делает задания и состояние аккаунтов
недоступными для расшифровки.
