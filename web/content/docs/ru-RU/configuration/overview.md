# Обзор конфигурации

RenoP хранит конфигурацию и состояние рядом с рабочей директорией процесса. Пути можно переопределить переменными
окружения.

## Файлы

| Файл                | Переопределение env  | Назначение                                              |
|---------------------|----------------------|---------------------------------------------------------|
| `config.yaml`       | `RENOP_CONFIG`       | Bind сервера, TLS, брендинг UI, путь хранилища, updater |
| `repositories.yaml` | `RENOP_REPOSITORIES` | Репозитории, зеркала, S3 на репозиторий                 |
| `tokens.yaml`       | `RENOP_TOKENS`       | Пользователи, роли, upload-токены                       |
| `index.json`        | `RENOP_INDEX`        | Кэш индекса артефактов                                  |
| `sessions.json`     | `RENOP_SESSIONS`     | Браузерные сессии входа                                 |

Связано с runtime:

| Переменная                     | По умолчанию | Назначение                           |
|--------------------------------|--------------|--------------------------------------|
| `RENOP_DEFAULT_ADMIN_PASSWORD` | генерируется | Пароль первой учётной записи `admin` |

## Структура `config.yaml`

### `storage_path`

Корневой каталог локального хранилища артефактов (стандартная раскладка под этим путём). Относительный путь по умолчанию
обычно `storage`.

### `server`

| Ключ                  | По умолчанию      | Описание                                                             |
|-----------------------|-------------------|----------------------------------------------------------------------|
| `host`                | `0.0.0.0`         | Адрес прослушивания                                                  |
| `port`                | `3000`            | Порт прослушивания                                                   |
| `ssl_enabled`         | `false`           | Включить TLS                                                         |
| `ssl_cert_path`       | `""`              | Путь к сертификату при включённом TLS                                |
| `ssl_key_path`        | `""`              | Путь к закрытому ключу при включённом TLS                            |
| `domain`              | `localhost`       | Публичное доменное имя (часть UI / метаданных)                       |
| `enable_compression`  | `false`           | Сжатие HTTP-ответов                                                  |
| `file_cache_size_mb`  | `100`             | Размер файлового кэша в памяти (МБ)                                  |
| `max_active_requests` | `2000`            | Лимит одновременных запросов (перегрузка → 503)                      |
| `trusted_proxies`     | `[]`              | Доп. CIDR/IP reverse proxy (loopback всегда доверен)                 |
| `cdn_ip_header`       | `X-Forwarded-For` | Заголовок IP клиента за доверенным прокси (напр. `CF-Connecting-IP`) |

После изменения host, port или TLS **перезапустите** процесс.

### `frontend`

Брендинг встроенного браузера репозитория:

| Ключ                   | Описание                                |
|------------------------|-----------------------------------------|
| `id`                   | ID фронтенда / сайта                    |
| `title`                | Заголовок страницы                      |
| `description`          | Краткое описание                        |
| `organization_website` | URL организации / продукта              |
| `organization_logo`    | Путь к логотипу (напр. `/svg/logo.svg`) |
| `background_url`       | Опциональный фон                        |
| `icp_license`          | Опциональный ICP / compliance-текст     |

### `updater`

| Ключ      | По умолчанию | Описание                                        |
|-----------|--------------|-------------------------------------------------|
| `channel` | `release`    | `release` или `nightly`                         |
| `mode`    | `manual`     | Как применяются обновления (напр. вручную в UI) |

Страница [Загрузки](/download) сайта использует те же источники release и nightly.

## UI управления

Вошедшие **manager** / **admin** могут править многие параметры в **Settings** и **Repositories**. Изменения на уровне
файлов применяются после reload/restart, как описано для каждого домена.

## Бэкенды хранилища

Артефакты могут жить:

- на **локальном диске** под `storage_path` (по умолчанию)
- в **S3-совместимом object storage** (глобально или на репозиторий в `repositories.yaml`)

При загрузке можно генерировать sidecar-контрольные суммы (MD5 / SHA-1 / SHA-256 / SHA-512).

См. [Репозитории и зеркала](./repositories.md) для visibility, зеркал и полей S3.
