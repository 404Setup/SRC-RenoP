# Подтверждение почты безопасности

## Изменение адреса

Измените закрытый адрес в разделе **Безопасность аккаунта**. Если отправка почты включена, сохранение добавляет письмо с подтверждением нового адреса в очередь. Введите восьмизначный код, чтобы применить изменение. Текущий адрес работает до успешного подтверждения. Если отправка отключена, адрес сохраняется сразу.

Настроенный чёрный или белый список применяется к обоим способам, в том числе при отключённой отправке. Правила принимают полный адрес, точный @домен или .суффикс с поддоменами. В режиме чёрного списка доступен встроенный список временной почты; белый список его игнорирует. Формы Unicode и Punycode одного международного домена соответствуют одному правилу. Нельзя занять адрес другого аккаунта или адрес, ещё зарезервированный закрытым аккаунтом.

## Дополнительные адреса для входа

Основной и дополнительные адреса используют единый реестр владельцев. Привязка отклоняется, если внешняя идентичность или любой возвращённый контактный адрес принадлежит другому аккаунту, в том числе удерживается после закрытия. Привязка, резервирование адресов и изменения безопасности фиксируются вместе; отказ не меняет существующий аккаунт. Адреса никогда не объединяют аккаунты.

**Другие адреса для входа** показывает закрытые дополнительные адреса. Они подходят для входа в тот же аккаунт с паролем или Passkey, сброса пароля по почте и офлайн-кодов восстановления. Существующие правила пароля и второго фактора сохраняются. Уведомления по-прежнему отправляются на основной адрес. Допускается не более 128 адресов на аккаунт, включая основной.

Адрес должен быть подтверждён провайдером либо уже принадлежать вошедшему аккаунту. Иначе подтвердите его у провайдера или используйте **Добавить и подтвердить адрес** перед привязкой. Добавление требует отправки писем RenoP и существующего диалога кода. При регистрации с неподтверждённым адресом провайдера нужно подтвердить именно его; подтверждение другого адреса не подходит. Адреса GitHub no-reply исключены.

Отключение провайдера сохраняет его адреса. Удаление дополнительного адреса освобождает его, но последующая авторизация провайдера может добавить его снова. Основной адрес нельзя удалить операцией удаления дополнительного. Блокировка сохраняет все адреса; после закрытия они удерживаются 14 дней, даже если основной адрес не задан. Досрочное освобождение администратором относится ко всем сохранённым адресам.

| Метод | Путь | Запрос или ответ |
|---|---|---|
| GET | `/api/auth/profile/security` | Добавляет `email_aliases` рядом с `email` |
| PUT | `/api/auth/profile/email` | `{"email":"alias@example.com","alias":true}`; `202` с квитанцией проверки |
| DELETE | `/api/auth/profile/email/alias` | `{"email":"alias@example.com"}`; обновлённая безопасность аккаунта |

Подтверждение использует существующий endpoint; назначение сохраняется вместе с запросом проверки и не может изменяться при подтверждении. Для удаления нужен вход в браузере за последние пять минут. Ошибки `ACCOUNT_EMAIL_PROOF_REQUIRED`, `ACCOUNT_EMAIL_LIMIT` и `ACCOUNT_EMAIL_PRIMARY` возвращают `409`; старая сессия при удалении получает `MFA_REAUTH_REQUIRED`.

Обновление заполняет владельцев существующих основных адресов. Старые привязки получают дополнительные адреса при следующей авторизации, поскольку раньше эти данные не сохранялись. Перед сохранением нового браузерного сеанса база повторно проверяет блокировку и срок действия аккаунта в его транзакции.

## API подтверждения

Операции требуют cookie текущего браузера. Тело JSON должно иметь `Content-Type: application/json`; предел — 4 096 байт.

| Метод | Путь | Запрос или ответ |
|---|---|---|
| GET | `/api/auth/profile/security` | Содержит `email` и `email_verification_required` |
| PUT | `/api/auth/profile/email` | `{"email":"new@example.com"}`; `202` с `{id,status,ticket}` при постановке в очередь, иначе `200` с состоянием безопасности |
| POST | `/api/auth/profile/email/confirm` | Адрес и код; `200` с обновлённым состоянием безопасности |
| GET | `/api/auth/mail/:id` | Статус доставки; доступ разрешён запросившему аккаунту или по `X-Renop-Mail-Ticket` |

```json
{"email":"new@example.com","code":"01234567"}
```

Код действует 10 минут, допускает пять неверных попыток и привязан к запросившей его сессии браузера. Новый код можно запросить через 60 секунд с учётом ограничения отправки по IP. Успешная постановка нового письма в очередь отменяет прежний код; при ошибке старый код сохраняется. Код, запись очереди и счётчик IP фиксируются одной транзакцией.

Неверный, просроченный, использованный или устаревший код возвращает `400` с `ACCOUNT_EMAIL_CODE_INVALID`; браузер остаётся в системе. Занятый адрес возвращает `409` с `ACCOUNT_EMAIL_CONFLICT`. Отказ политики получателей возвращает `400` с `mail_recipient_blocked`. Отозванная сессия не может подтвердить изменение. Изменение учётных данных или настроек безопасности также отменяет ожидающие подтверждения.

## Подтверждение через GitHub

Если вход через GitHub настроен, действие **Использовать подтверждённую почту GitHub** разрешает новый запрос через `GET /api/auth/github/start?intent=email`. Этот сценарий запрашивает `user:email` и читает [список адресов авторизованного пользователя GitHub](https://docs.github.com/en/rest/users/emails#list-email-addresses-for-the-authenticated-user).

RenoP выбирает подтверждённый основной контактный адрес, а при его отсутствии — первый подтверждённый контактный адрес. Адреса no-reply GitHub исключаются. Полученный адрес проверяется по локальной политике и сохраняется. Способ работает без настроенного отправителя и не создаёт и не заменяет привязку входа GitHub.

Обратный вызов одноразовый, действует 10 минут и должен вернуться к исходному аккаунту и сессии браузера с неизменными учётными данными. Токены провайдера используются только для этого запроса и не сохраняются.

## Эксплуатация

RenoP хранит не более 2 048 ожидающих изменений почты. Просроченные записи удаляются перед добавлением новых и при очистке почтовых данных. Коды сохраняются как хеши с ключом; содержимое писем в очереди шифруется закрытым почтовым ключом. Коды и билеты доставки не попадают в URL, журналы или хранилище браузера.

Успешное изменение создаёт запись активности профиля. Последовательный почтовый обработчик отправляет уведомление `email_changed` согласно маршрутизации и ограничениям отправки. Постановка в очередь не означает доставку; окно подтверждения показывает ход доставки и ошибки провайдера.

Другие провайдеры могут предлагать [Использовать подтверждённую почту](./oauth-login.md) в редакторе профиля. Операция также требует новой авторизации, сохраняет текущую привязку и учитывает политику получателей. Без явного утверждения о подтверждении адрес нужно проверить кодом RenoP.
## Язык учётной записи

При входе на каждом устройстве восстанавливается сохранённый язык учётной записи. Если предпочтение ещё не задано, используется текущий язык интерфейса; последующие изменения в выборе языка сохраняются автоматически. При регистрации язык страницы сохраняется вместе с новой учётной записью. При ошибке на устройстве остаётся один ожидающий выбор; отправка повторяется после восстановления соединения, возврата на страницу или её перезагрузки. Выбор предыдущей учётной записи никогда не применяется к другой.

Предпочтение является частным, сохраняется после переименования и перезапуска и удаляется при закрытии учётной записи. Его изменение не меняет учётные данные и не отменяет текущую двухэтапную проверку. Фоновые уведомления и письма для сброса пароля используют язык получателя, в том числе при идентификации по почтовому псевдониму. При отсутствии предпочтения используется `Accept-Language` исходной страницы, затем `en-US`. Письма в очереди сохраняют язык, выбранный при постановке в очередь.

Поддерживаются идентификаторы `en-US`, `zh-CN`, `zh-HK`, `zh-TW`, `zh-YUE`, `ko-KR`, `ja-JP`, `de-DE`, `fr-FR`, `ru-RU`, `es-ES` и `pt-PT`.

| Метод | Путь | Запрос или ответ |
|---|---|---|
| GET | `/api/auth/profile/locale` | `{"user_id":"00000000-0000-4000-8000-000000000001","locale":"fr-FR"}`; пустое значение означает отсутствие предпочтения |
| PUT | `/api/auth/profile/locale` | `{"user_id":"00000000-0000-4000-8000-000000000001","locale":"fr-FR"}`; возвращает сохранённый канонический идентификатор |

Обе операции требуют текущий cookie браузера и возвращают `Cache-Control: no-store` для данных предпочтения. Токены API не могут читать или менять эту настройку. Неподдерживаемое значение возвращает `400` с `ACCOUNT_LOCALE_INVALID`. В [настройках почты](../configuration/mail.md) больше нет общего переключателя языка.

PUT должен передавать неизменяемый `user_id` из GET; несовпадение учётной записи возвращает `403`. Локальные ожидающие изменения также привязаны к этому ID, поэтому переименование или повторное использование имени не переносит предпочтение между учётными записями.
