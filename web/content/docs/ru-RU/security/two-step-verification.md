# Двухэтапная проверка

## Поведение при входе

Настройте двухэтапную проверку в панели безопасности учётной записи. После успешной проверки пароля или сторонней
учётной записи RenoP требует настроенный второй фактор и только затем создаёт сеанс браузера. Если включены и
аутентификатор, и вторичный Passkey, достаточно любого из них. Вторичный Passkey нельзя использовать для
самостоятельного входа. После входа с основным Passkey можно запросить код аутентификатора.

Если нужен второй фактор, вход с паролем или основным Passkey возвращает `409` с `X-Renop-Error-Code: MFA_REQUIRED`.
GitHub и другие настроенные провайдеры OAuth перенаправляют на `/account/login?mfa=1`, сохраняя локальный адрес
`return_to`. Закрытый HttpOnly cookie `renop_mfa` разрешает только завершение ожидающей проверки и не является сеансом.
Запросы проверки действуют пять минут, используются один раз и удаляются при перезапуске. Процесс хранит не более 4 096
запросов и восьми на учётную запись.

При входе с Passkey, проверке второго фактора и регистрации на нажатой кнопке отображается обратный отсчёт. Ожидание
каждого системного запроса ограничено 60 секундами или меньшим сроком, заданным сервером. По истечении срока запрос
отменяется, а попытка входа завершается вместе с ожидающим вторым фактором; запоздавшие данные отбрасываются. Для
повторной попытки начните вход заново. Уход со страницы также отменяет незавершённые запросы. Отмена, отсутствие или
отказ в доступе к данным, неподдерживаемая или небезопасная среда, повторная регистрация и невыполнимые требования
проверки показываются переведёнными сообщениями без раскрытия исключений браузера.

## Настройка аутентификатора

Нажмите **Настроить** рядом с **Приложение-аутентификатор**. Отсканируйте QR-код или введите ключ вручную: по времени,
SHA-1, шесть цифр, период 30 секунд. QR-код создаёт RenoP, данные настройки не передаются внешним сервисам. Подтвердите
настройку кодом приложения в течение пяти минут. Без подтверждения политика входа не меняется.

Коды соответствуют [RFC 6238](https://www.rfc-editor.org/info/rfc6238/) с допуском одного периода до и после времени
сервера. Синхронизируйте часы сервера и устройства. Успешно использованный счётчик нельзя использовать повторно, включая
подтверждение настройки; при необходимости дождитесь нового кода. После пяти отклонённых кодов в пятиминутном окне
дальнейшие попытки для учётной записи блокируются до конца окна. Новый запрос входа не сбрасывает ограничение.

## Passkey как второй фактор

Зарегистрируйте Passkey перед включением **Passkey как второй фактор**. Пароль или связанная сторонняя учётная запись
должны оставаться основным способом входа. RenoP запрещает отключать последний основной способ и удалять последний
вторичный Passkey, пока настройка включена. Сначала отключите настройку, затем удаляйте последний Passkey. Вторичные
утверждения требуют проверки пользователя WebAuthn.

## API проверки

Все JSON-тела POST/PUT ниже требуют `Content-Type: application/json` и ограничены 4 096 байтами. Для изменения профиля
нужны текущий cookie браузера и вход не более пяти минут назад; старый сеанс получает `MFA_REAUTH_REQUIRED`. Успешные
изменения отзывают остальные сеансы. Ответ о безопасности содержит логические поля `totp_enabled` и
`passkey_second_factor`, но не ключ аутентификатора.

| Метод  | Путь                                 | Тело JSON или результат                                                  |
|--------|--------------------------------------|--------------------------------------------------------------------------|
| GET    | `/api/auth/mfa`                      | `{totp,passkey,expires_at}`                                              |
| DELETE | `/api/auth/mfa`                      | `204`                                                                    |
| POST   | `/api/auth/mfa/totp`                 | `{"code":"012345"}`                                                      |
| POST   | `/api/auth/mfa/passkey/begin`        | `{}` → `{options}`                                                       |
| POST   | `/api/auth/mfa/passkey/finish`       | `{credential}` → session                                                 |
| POST   | `/api/auth/profile/mfa/totp/begin`   | `{}` → `{id,secret,uri,qr,expires_at}`                                   |
| POST   | `/api/auth/profile/mfa/totp/confirm` | `{"id":"setup-id","code":"012345"}` → security                           |
| PUT    | `/api/auth/profile/mfa`              | `{"passkey_second_factor":true}` или `{"totp_enabled":false}` → security |

```json
{"totp_enabled":true,"passkey_second_factor":true}
```

Не помещайте коды, QR-изображения, ключи настройки или cookie проверки в URL, журналы или хранилище браузера. Ошибки
проверки используют `MFA_INVALID`, сбои сервиса — `MFA_UNAVAILABLE`, а самостоятельный вход с вторичным Passkey
возвращает `MFA_PRIMARY_REQUIRED`. Успешная проверка возвращает сведения о сеансе в JSON и устанавливает обычный
HttpOnly cookie сеанса.

## Восстановление и эксплуатация

Четыре неиспользованных офлайн-кода восстановления в одной транзакции сбрасывают пароль, удаляют аутентификатор,
отключают вторичный режим Passkey и отзывают все сеансы. Зарегистрированные Passkey остаются привязаны и снова доступны
для основного входа. Восстановление пароля по email сохраняет настройки второго фактора. Храните офлайн-коды в
безопасном месте и настройте проверку заново после восстановления.

Для клиентов пакетов и автоматизации учётные записи с любым вторым фактором должны использовать API-токены: пароль
отклоняется при протокольной аутентификации. Существующие токены с ограниченными правами и перенесённые токены загрузки
сохраняют свои разрешения. После отключения двухэтапной проверки пароль снова принимается протоколами, если вход по
паролю включён.

При запуске RenoP создаёт закрытый ключ `mfa_encryption_key` на верхнем уровне конфигурации. Ключи аутентификатора
шифруются AES-GCM и связываются с неизменяемыми ID пользователей. Ключ шифрования не возвращается API настроек.
Сохраняйте конфигурацию вместе с базой данных и переносите ключ при миграции. Его потеря делает проверку
аутентификатором невозможной; восстановите доступ с помощью офлайн-кодов.
