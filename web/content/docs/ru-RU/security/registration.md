# Регистрация учётных записей

## Настройки регистрации

Регистрация по умолчанию отключена. Администратор может включить её в настройках службы. При отключении `/account/register` и операции регистрации возвращают `404`; публичный статус остаётся доступен. Значения конфигурации верхнего уровня по умолчанию:

```yaml
registration:
  enabled: false
  ip_limit: 1
  ip_interval: {value: 3, unit: week}
  provider_cooldown: {value: 12, unit: hour}
```

Лимит IP расходуют только успешные регистрации: по умолчанию одна учётная запись за три недели, начиная с первой успешной регистрации. Эквивалентные записи IPv4 и IPv6 используют общий лимит. Закрытие учётной записи не восстанавливает квоту, а перезапуск не сбрасывает ограничения. Число должно быть от 1 до 10 000; интервалы положительные, с единицами `minute`, `hour`, `day`, `week` или `month`, не более 365 дней. Месяц равен 30 дням.

## Создание учётной записи

Откройте регистрацию со страницы входа. Имя пользователя содержит 4–18 букв ASCII, цифр или знаков подчёркивания и сохраняется в нижнем регистре. Необязательное отображаемое имя допускает 36 символов Unicode. Обязательный пароль содержит 6–72 байта UTF-8.

Если отправка почты включена, необходимы адрес и восьмизначный код подтверждения. Код действует десять минут и допускает пять ошибок. Подтверждайте в том же браузере и с того же IP. Отправка использует существующую последовательную очередь, политику получателей, квоты и ограничения скорости; страница показывает статус доставки. Без почты адрес необязателен. После успеха войдите с новыми данными; при включённой почте уведомление об успешной регистрации также поступает в очередь.

## Регистрация через GitHub

Вход через GitHub без локальной привязки открывает подтверждение. RenoP запрашивает `read:user read:org user:email`, выбирает проверенный действительный контактный адрес и исключает no-reply. Почтовый код не нужен. Авторизация связана с браузером через HttpOnly cookie на десять минут; каждое состояние обратного вызова используется один раз.

Подтвердите регистрацию за десять минут и задайте пароль. До подтверждения рабочей учётной записи нет. После истечения срока личные данные ожидания удаляются, а повторная регистрация той же идентичности GitHub блокируется на заданный срок, по умолчанию двенадцать часов после истечения. Импорт имени, отображаемого имени и аватара необязателен. Действуют локальные ограничения; недоступное имя вводится вручную. Отсутствие необязательных данных или превышение аватаром размера либо квоты не препятствует регистрации.

## API регистрации

Публичные JSON-запросы требуют `Content-Type: application/json` и ограничены 4 096 байтами. Подтверждение также использует закрытый HttpOnly cookie регистрации; не сохраняйте пароль, код или почтовый билет в хранилище браузера.

- `GET /api/auth/registration/status`: Получить доступность и требования к почте.
- `GET /api/auth/registration/pending`: Получить ожидающее подтверждение этого браузера.
- `POST /api/auth/registration/code`: Поставить код в очередь; возвращает `202` и закрытую квитанцию.
- `POST /api/auth/registration`: Подтвердить регистрацию.
- `GET /api/settings/registration`, `PUT /api/settings/registration`: Читать или обновлять настройки регистрации (администратор).

```json
{
  "username": "new_user",
  "nickname": "New User",
  "email": "user@example.com",
  "password": "a unique long password",
  "code": "12345678"
}
```

Для подтверждения GitHub используйте `provider: "github"`, сохраните проверенный адрес и опустите `code`. Значение `true` для `import_avatar` запрашивает импорт аватара. Успех возвращает `201`, `username` и `avatar_imported`, не создавая сеанс входа. Конфликты возвращают `409`, неверное или истёкшее подтверждение — `400`, исчерпание лимита IP или срок ожидания провайдера — `429`. Учётная запись, почта, привязка, счётчик IP и использование подтверждения фиксируются одной транзакцией.
