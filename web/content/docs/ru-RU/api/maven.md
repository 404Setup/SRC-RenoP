# API реестра Maven

Репозитории Maven в RenoP используют проверенные пространства имён в формате обратного домена. Издатель один раз
резервирует домен в меню аккаунта и использует его во всех разрешённых Maven-репозиториях. Пути Maven 2, метаданные,
отделённые подписи и контрольные суммы совместимы с Maven и Gradle.

## Проверка домена

Создайте домен через `POST /api/maven/domains`. RenoP возвращает стойкий случайный код и место публикации
доказательства.

- Для DNS создайте TXT в зарегистрированном корне. RenoP читает все TXT и принимает только точное совпадение.
- `io.github.<account>` использует Bio публичного пользователя GitHub или Description публичной организации.
- `io.gitlab.<account>` использует Bio публичного пользователя GitLab или Description публичной группы.

Запустите проверку через `POST /api/maven/domains/:domain/verify`. Для одного домена разрешена одна попытка в пять
секунд. Системный администратор может вызвать `/verify/force`; действие фиксируется в журнале аудита.

Проверенный домен и его команда глобальны для экземпляра. В других Maven-репозиториях повторная проверка и приглашения
не требуются.

Недавняя привязка GitLab.com также может автоматически подтвердить новое пространство: аккаунт должен владеть личным
пространством или группой верхнего уровня, а доказательство должно быть получено менее часа назад. Публичного участия,
владения подгруппой или собственного экземпляра недостаточно.
См. [Вход через сторонние сервисы](../security/oauth-login.md).

## Права домена

Команда Maven относится к глобальному домену, а не к репозиторию или отдельному артефакту.

- L0: чтение публичного содержимого
- L1: публикация артефактов
- L2: управление версиями и описаниями
- L3: приглашение и управление участниками
- L4: владение и передача домена

Один запрос приглашения принимает от одного до двадцати имён. Добавления не от администратора оформляются через центр
сообщений. При передаче сохраняется ровно один владелец L4; владелец не может выйти до передачи прав.

## Каталог артефактов

`GET /api/maven/repositories/:repo/domains` возвращает домены с артефактами в выбранном репозитории.
`GET /api/maven/repositories/:repo/packages` предоставляет поиск с пагинацией.
`GET /api/maven/repositories/:repo/package?group=...&artifact=...` возвращает артефакт и его версии. Участники L2 могут
изменять описание и удалять полные версии через связанные JSON-маршруты.

Подробный ответ содержит сводку индексированных основных файлов, их размеров и времени изменения, доступных
контрольных сумм и отделённых подписей. Для каждой версии возвращается не более 64 основных файлов. Если последний
индексированный POM не превышает 2 МиБ, RenoP разбирает его потоково и также возвращает сведения о проекте,
организации, лицензиях, разработчиках, управлении исходным кодом, системе задач, родительском проекте и прямых
зависимостях. Число прямых зависимостей ограничено 128; сопутствующие файлы контрольных сумм и подписей не считаются
основными.

Участник домена L2-L4 или администратор может вести отдельный Markdown README уровня пакета через эндпоинт обновления
артефакта. Размер ограничен 512 КиБ, README возвращается только детальным эндпоинтом и отображается через общий список
разрешённых элементов и URL. Краткое описание POM или каталога остаётся отдельным полем.

Старые репозитории индексируются при обновлении. Импортированные домены считаются проверенными, но участники не
назначаются автоматически. Настроенные зеркала Maven продолжают разрешать отсутствующие артефакты.

## Представления и файловые репозитории

По умолчанию интерфейс показывает каталог доменов. Администратор может включить классическое дерево файлов и позднее
вернуться обратно. Меняется только представление: произвольные пути запрещены, а публикация требует проверенный домен и
корректный путь Maven.

Отдельный формат `files` предназначен для неструктурированных данных. Он поддерживает замену, удаление, S3 и зеркала,
но не создаёт контрольные суммы или POM и не выполняет проверку OpenPGP.

## Доступ Maven и Gradle

Чтение и публикация используют `/{repo}/{maven-path}`. Применяйте пароль или API Token с `repository:read` и/или
`repository:publish`. Видимость управляет чтением, а проверенный домен и уровень L0-L4 аккаунта — изменениями. Полный
контракт находится в `web/assets/openapi.yaml`.

## Блокировки ресурсов

Администраторы и модераторы этого репозитория управляют блокировками артефактов и версий с действующим cookie браузерной
сессии:

- `PUT /api/maven/repositories/{repo_name}/package/locks?group={group}&artifact={artifact}`
- `DELETE /api/maven/repositories/{repo_name}/package/locks?group={group}&artifact={artifact}`

```json
{"version":"1.2.3","mode":"read","reason":"trojan"}
```

Отсутствующее или пустое поле `version` означает весь артефакт. DELETE принимает `{"version":"1.2.3"}` и удаляет только
эту ручную блокировку; системные блокировки сохраняются независимо. API Tokens не могут управлять блокировками.
Интерфейс переводит публичные причины: `hold`, `prohibited`, `expired`, `trojan`, `abuse`, `dmca`, `reup`, `squatting`,
`quality`.

Оба режима запрещают запись. `write` сохраняет загрузку имеющихся файлов; `read` также разрешает метаданные только
администраторам, модераторам репозитория, владельцам и участникам домена (включая L0) и участникам глобальных команд,
связанных с доменом или артефактом. Никто не может скачивать содержимое файлов, POM, подписи и контрольные суммы.
Уполномоченные пользователи могут просматривать каталог и разобранные данные `maven-metadata.xml`; остальные не видят
ограниченные артефакты и версии в каталоге, поиске, списках файлов, API версий и статистике. Общий XML исключает скрытые
версии и корректирует latest/release, не меняя сохранённый файл.

Блокировки охватывают произвольные сопутствующие файлы и SNAPSHOT с временными метками. Замороженные файлы не удаляются
по истечении срока кеша и не загружаются заново с зеркал. Пока версия заблокирована, нельзя заменять общие метаданные;
также запрещены постоянное устаревание всего артефакта, перенастройка и удаление репозитория. Ответы содержат публичные
`locks`, `moderator`, `member`, `version_locked`. Запрещённые изменения возвращают `423` и
`X-Renop-Error-Code: resource_locked`, запрещённое чтение — `404`.

Удаление версии проверяет каждый сегмент координат до изменения хранилища; разделители пути и точечные псевдонимы
каталогов запрещены.

Блокировки глобальной команды наследуются связанными пакетами и доменами публикации. Ответы доменов включают публичные
`locks`. Блокировка домена запрещает подтверждение, изменение участников, передачу владения, закрытие и новые
публикации, включая неиндексированные файлы и метаданные. Блокировка чтения сохраняет доступ к метаданным для
существующих участников и уполномоченных модераторов, запрещая всем содержимое файлов. Независимо подтверждённый
дочерний домен сохраняет собственные полномочия. Членство и права на домен сохраняются и восстанавливаются после снятия
всех применимых ограничений.

Системные администраторы и глобальные модераторы управляют блокировкой домена во всех репозиториях через активную сессию
браузера:

- `PUT /api/maven/domains/{domain}/locks`
- `DELETE /api/maven/domains/{domain}/locks`

```json
{"mode":"write","reason":"hold"}
```

PUT принимает тело ниже, DELETE — `{}`. Оба возвращают `204`. API-токены и модераторы отдельных репозиториев не могут
управлять глобальным доменом. Снятие ручной блокировки сохраняет системные ограничения и блокировки, унаследованные от
команды. Поле `moderator` в сведениях о домене отражает права текущего запроса; публичная страница, страница аккаунта и
страница домена в репозитории используют общий элемент управления. Изменение, миграция и удаление репозитория также
проверяют заблокированные пространства имён, существующие только на диске или в файловом индексе.

## Состояние домена и восстановление прав

RenoP проверяет зарегистрированные домены по RDAP с
помощью [начальных данных IANA](https://data.iana.org/rdap/dns.json).
Каждую минуту обрабатывается до 16 доменов; успешные проверки повторяются через шесть часов, недоступные — через 15
минут.

| Состояние реестра                                                                                 | Публичная причина блокировки |
|---------------------------------------------------------------------------------------------------|------------------------------|
| `serverHold`, `clientHold`                                                                        | `hold`                       |
| `pendingDelete`, `restorable`, `redemptionPeriod`, `pendingRestore` или истёкший срок регистрации | `expired`                    |
| `clientRenewProhibited`, `serverRenewProhibited`, `renew prohibited`                              | `prohibited`                 |

Поддерживаются эквивалентные записи RDAP с пробелами. Сбой провайдера не снимает ограничение и не продлевает известный
срок регистрации.
Недоступный реестр не позволяет завершить новую проверку. Подтверждение владения и одобрение заявки администратором
требуют нормального состояния.

Для `io.github.<account>` и `io.gitlab.<account>` проверяется публичный аккаунт, а не срок регистрации домена.
При проверке сохраняются неизменяемый числовой ID и тип: пользователь или организация/группа.
Отсутствие аккаунта блокирует публикацию; изменение ID или типа считается спором, даже если имя осталось прежним.
Старые подтверждённые пространства без сохранённого ID требуют нового доказательства перед восстановлением прав.

Блокировка состояния запрещает запись в домен и его содержимое, сохраняя загрузки и список участников.
Первая блокировка заменяет код проверки. После восстановления внешнего аккаунта или домена текущий владелец L4
публикует новое доказательство и выбирает **Запросить восстановление**:
`POST /api/maven/domains/{domain}/redeem` с действующим cookie `renop_session`.
Допускается одна попытка на домен каждые пять секунд. Успешная фоновая проверка сама по себе не возвращает управление.
Восстановление снимает только блокировку состояния; независимые ручные, системные и командные ограничения сохраняются.
Поле `health` содержит состояние, время проверки и истечения срока, данные провайдера, время блокировки и освобождения.

## Старые пакеты освобождённого домена

По умолчанию защитная блокировка резервирует имя на два календарных года.
[Настройки домена](settings.md) принимают период 1–100 месяцев или лет; изменения действуют для новых блокировок.
Добровольное закрытие сохраняет отдельный срок в 31 день. После освобождения новый заявитель обязан доказать владение
и получить одобрение администратора с новой проверкой состояния.

Старые пакеты, включая ранее отсутствовавшие в каталоге индексированные файлы, сохраняют загрузки, но остаются
недоступными для записи.
После одобрения домена можно публиковать новые имена пакетов.
Текущий владелец домена запрашивает права со страницы старого пакета через `POST /api/tickets/maven-restorations`.
Требуется одобрение модератора репозитория или системного администратора.
При одобрении повторно проверяются заявка и владелец; восстанавливается только этот пакет и его связь с текущей командой
домена.
Зеркальные и окончательно упразднённые пакеты не восстанавливаются. См. [API проверки](reviews.md).

Подготовка заявки последовательно читает метаданные диска или S3 с ограничением в одну минуту. Ошибка хранилища или
тайм-аут не меняет текущую заявку.
Ожидающие проверки публикации сохраняют прежний процесс рассмотрения и не импортируются в публичный каталог.

Страницы пакетов предоставляют администраторам и участникам L3/L4 переход к команде домена. Открывается существующая страница домена публикации; изменения участников действуют для всех его пакетов, включая импортированные. Длинные координаты переносятся отдельно от кнопок. Сведения об артефакте и последнем POM занимают всю ширину, а форматы зависимостей переключаются с анимацией и с клавиатуры.

Диалог блокировки позволяет напрямую снять ручную блокировку выбранного ресурса. Унаследованные ограничения меняются у домена или глобальной команды; системные блокировки сохраняют существующие процедуры возврата и восстановления.

Каталог и подробности Maven возвращают блокировки пакета, включая унаследованные. Интерфейс показывает метку и явную кнопку разблокировки его ручного ограничения. Не заблокировано означает снятие этого ручного ограничения, сохраняя родительские и системные.

Все API блокировки принимают `reason: custom` с непустым `reason_text` длиной до 256 символов. Причина видна читателям ресурса как обычный текст и не допускает управляющих символов. Для стандартных причин поле `reason_text` не передаётся.

```json
{"mode":"write","reason":"custom","reason_text":"Awaiting source verification"}
```
