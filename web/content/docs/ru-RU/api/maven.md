# API реестра Maven

Репозитории Maven в RenoP используют проверенные пространства имён в формате обратного домена. Издатель один раз
резервирует домен в меню аккаунта и использует его во всех разрешённых Maven-репозиториях. Пути Maven 2, метаданные,
отделённые подписи и контрольные суммы совместимы с Maven и Gradle.

## Проверка домена

Создайте домен через `POST /api/maven/domains`. RenoP возвращает стойкий случайный код и место публикации доказательства.

- Для DNS создайте TXT в зарегистрированном корне. RenoP читает все TXT и принимает только точное совпадение.
- `io.github.<account>` использует Bio публичного пользователя GitHub или Description публичной организации.
- `io.gitlab.<account>` использует Bio публичного пользователя GitLab или Description публичной группы.

Запустите проверку через `POST /api/maven/domains/:domain/verify`. Для одного домена разрешена одна попытка в пять
секунд. Системный администратор может вызвать `/verify/force`; действие фиксируется в журнале аудита.

Проверенный домен и его команда глобальны для экземпляра. В других Maven-репозиториях повторная проверка и приглашения
не требуются.

## Права домена

Команда Maven относится к глобальному домену, а не к репозиторию или отдельному артефакту.

- L0: чтение публичного содержимого
- L1: публикация артефактов
- L2: управление версиями и описаниями
- L3: приглашение и управление участниками
- L4: владение и передача домена

Один запрос приглашения принимает от одного до двадцати имён. Добавления не от администратора оформляются через центр
сообщений. При передаче сохраняется ровно один владелец L4; владелец не может выйти до передачи прав.

## Каталог артефактов

`GET /api/maven/repositories/:repo/domains` возвращает домены с артефактами в выбранном репозитории.
`GET /api/maven/repositories/:repo/packages` предоставляет поиск с пагинацией.
`GET /api/maven/repositories/:repo/package?group=...&artifact=...` возвращает артефакт и его версии. Участники L2 могут
изменять описание и удалять полные версии через связанные JSON-маршруты.

Подробный ответ содержит сводку индексированных основных файлов, их размеров и времени изменения, доступных
контрольных сумм и отделённых подписей. Для каждой версии возвращается не более 64 основных файлов. Если последний
индексированный POM не превышает 2 МиБ, RenoP разбирает его потоково и также возвращает сведения о проекте,
организации, лицензиях, разработчиках, управлении исходным кодом, системе задач, родительском проекте и прямых
зависимостях. Число прямых зависимостей ограничено 128; сопутствующие файлы контрольных сумм и подписей не считаются
основными.

Участник домена L2-L4 или администратор может вести отдельный Markdown README уровня пакета через эндпоинт обновления
артефакта. Размер ограничен 512 КиБ, README возвращается только детальным эндпоинтом и отображается через общий список
разрешённых элементов и URL. Краткое описание POM или каталога остаётся отдельным полем.

Старые репозитории индексируются при обновлении. Импортированные домены считаются проверенными, но участники не
назначаются автоматически. Настроенные зеркала Maven продолжают разрешать отсутствующие артефакты.

## Представления и файловые репозитории

По умолчанию интерфейс показывает каталог доменов. Администратор может включить классическое дерево файлов и позднее
вернуться обратно. Меняется только представление: произвольные пути запрещены, а публикация требует проверенный домен и
корректный путь Maven.

Отдельный формат `files` предназначен для неструктурированных данных. Он поддерживает замену, удаление, S3 и зеркала,
но не создаёт контрольные суммы или POM и не выполняет проверку OpenPGP.

## Доступ Maven и Gradle

Чтение и публикация используют `/{repo}/{maven-path}`. Применяйте пароль или API Token с `repository:read` и/или
`repository:publish`. Видимость управляет чтением, а проверенный домен и уровень L0-L4 аккаунта — изменениями. Полный
контракт находится в `web/assets/openapi.yaml`.
