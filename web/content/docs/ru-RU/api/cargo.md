# API реестра Cargo

RenoP реализует спецификации Cargo Registry и Sparse Index.

## Настройка Sparse Index (`config.json`)

- **Путь**: `GET /{repo}/config.json` или `GET /{repo}/index/config.json`
- **Назначение**: Cargo читает документ при первом подключении и узнаёт маршруты реестра.

### Ответ JSON

```json
{
  "dl": "http://localhost:3000/{repo}/api/v1/crates",
  "api": "http://localhost:3000/{repo}",
  "auth-required": false
}
```

---

## Метаданные Sparse Index

- **Путь**: `GET /{repo}/index/{prefix}/{crate_name}`
- **Назначение**: возвращает построчный JSON по стандартным правилам сегментации имён Cargo.

---

## Публикация crate

- **Путь**: `PUT /{repo}/api/v1/crates/new`
- **Аутентификация**: Token в `Authorization: <token>`.
- **Тело**: 4-байтовая длина JSON, метаданные JSON и бинарный архив `.crate`.
- **Конфликт имени**: первая публикация возвращает `409 Conflict`, если нормализованное имя занято локально или на
  применимом зеркале. Если проверка upstream не дала результата, возвращается `503 Service Unavailable`.

Для локальной публикации RenoP читает `package.readme` из проверенного `Cargo.toml` и извлекает указанный файл из
архива, не загружая crate целиком в память. Подробный ответ содержит не более 512 КиБ Markdown; браузер отображает его
через общий список разрешённых элементов и URL. Каталог и поиск не загружают содержимое README.

---

## Скачивание crate

- **Путь**: `GET /{repo}/api/v1/crates/{crate_name}/{version}/download`
- **Ответ**: архив `.crate` с типом `application/x-tar`.

---

## Yank и unyank

- **Yank**: `DELETE /{repo}/api/v1/crates/{crate_name}/{version}/yank`
- **Unyank**: `PUT /{repo}/api/v1/crates/{crate_name}/{version}/unyank`
- **Аутентификация**: владелец crate или администратор.

## Блокировка ресурсов

Администраторы и модераторы этого репозитория вызывают `PUT /{repo}/api/v1/crates/{crate_name}/locks`
с cookie активной сессии браузера. Токены API и учётные данные пакетных клиентов не позволяют управлять блокировками.

```json
{"version":"1.2.3","mode":"read","reason":"trojan"}
```

Для всего пакета пропустите `version` или укажите `""`. Режимы: `write` и `read`. Публичные переводимые причины:
`hold`, `prohibited`, `expired`, `trojan`, `abuse`, `dmca`, `reup`, `squatting`, `quality`.
Успешное изменение возвращает `{"ok":true}`. Для удаления конкретной ручной блокировки отправьте
`DELETE /{repo}/api/v1/crates/{crate_name}/locks` с телом `{"version":"1.2.3"}`.

Блокировка записи запрещает изменения и обновления из upstream, сохраняя скачивание уже сохранённых файлов.
Блокировка чтения также запрещает скачивание файлов и просмотр документации всем, включая сотрудников.
Метаданные доступны администраторам, модераторам репозитория, владельцам и участникам, включая L0 и участников
связанной глобальной команды. Остальные посетители не видят заблокированный пакет или версию в метаданных,
sparse-индексах, поиске, профилях и списках ресурсов команд.

Метаданные пакета и версии содержат публичные записи `locks` с полями `mode`, `reason`, `source`, `locked_at`.
Ручные и системные блокировки независимы: удаление ручной не отменяет системные ограничения.
Запрещённые изменения возвращают `423` и `X-Renop-Error-Code: resource_locked`, чтение — `404`.
Блокировка версии запрещает архивацию, окончательный вывод из эксплуатации и удаление всего пакета, но позволяет
публиковать другие версии. Перенастройка и удаление репозитория запрещены, пока в нём есть блокировки ресурсов.
