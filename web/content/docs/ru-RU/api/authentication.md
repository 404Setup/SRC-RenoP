# API аутентификации

Браузер использует HttpOnly cookie `renop_session`. Его секрет не возвращается API профиля и списка сессий и не
принимается в заголовках или URL. Закрытые настройки безопасности доступны только через браузерную сессию, не по
паролю или API Token.

Страница входа в браузере находится по адресу `/account/login`. После входа с паролем, Passkey или сторонним провайдером
пользователь возвращается к локальному пути из необязательного параметра `return_to`; строка запроса и фрагмент не
сохраняются. Внешние адреса, конечные точки аутентификации и значения длиннее 1 024 символов заменяются на `/`. При
истечении сеанса открывается страница входа; при отказе в доступе авторизованный пользователь возвращается на главную
страницу без завершения сеанса.

Раздел [двухэтапной проверки](../security/two-step-verification.md) описывает настройку аутентификатора, вторичные
Passkey, ожидающие ответы входа и восстановление. Вторичный Passkey не считается основным способом входа.
Офлайн-восстановление удаляет аутентификатор и отключает вторичные Passkey; восстановление по email сохраняет оба
параметра.

## Вход по паролю или e-mail

- **Путь**: `POST /api/auth/login`
- **Аутентификация**: не требуется.
- **Тело**: JSON / protobuf `LoginRequest`; ниже показаны имена JSON. `name` принимает имя пользователя или закрытый e-mail.

### Запрос

```json
{
  "name": "admin",
  "secret": "your_password"
}
```

### Результат сессии

Успех устанавливает `renop_session` с `HttpOnly`, `SameSite=Lax` и `Secure` при HTTPS. Protobuf `SessionDetails`
содержит права и маршруты аккаунта, но оставляет `session_token` пустым.

## Вход Passkey и GitHub

- **Начало Passkey**: `POST /api/auth/fido/login/begin`
- **Завершение Passkey**: `POST /api/auth/fido/login/finish`
- **Начало GitHub**: `GET /api/auth/oauth/github/start` (`GET /api/auth/github/start`)
- **Callback GitHub**: `GET /api/auth/github/callback`
- **Доступность GitHub**: `GET /api/auth/github/status`

GitHub отображается только после настройки OAuth администратором. RenoP запрашивает чтение пользователя и организаций,
сохраняет неизменяемые Provider ID и снимки principals, но не сохраняет OAuth Access Token.

Непривязанные идентичности GitHub требуют [регистрации](../security/registration.md) и пароля. OAuth запрашивает
`read:user read:org user:email`; обратный вызов требует cookie браузера, начавшего авторизацию.

Microsoft, Google, GitLab, Cloudflare, Stack Exchange и собственные клиенты OAuth
используют [API стороннего входа](../security/oauth-login.md). Доступны привязки аккаунтов, обязательная при
необходимости проверка почты при регистрации, необязательный импорт профиля и та же политика второго фактора.

## Текущий аккаунт и публичные профили

- **Текущая сессия**: `GET /api/auth/me`
- **Закрытый профиль**: `GET /api/auth/profile`
- **Изменить имя или псевдоним**: `PUT /api/auth/profile`
- **Изменить пароль**: `PUT /api/auth/profile/password`
- **Выйти**: `POST /api/auth/logout`
- **Публичный профиль**: `GET /api/users/:username/profile`
- **Участие в пакетах**: `GET /api/users/:username/memberships?format=cargo|docker|maven|npm`

Видимые маршруты используют имя, а неизменяемый ID остаётся внутренним. Участие в `HIDDEN` не возвращается; закрытые
связи видит только авторизованный пользователь.

## Безопасность аккаунта

Эти маршруты требуют текущую браузерную сессию и возвращают `Cache-Control: no-store`.

### E-mail и политика входа по паролю

- **Состояние**: `GET /api/auth/profile/security`
- **Задать e-mail**: `PUT /api/auth/profile/email`; подтверждение письмом из очереди и через GitHub описано в
  разделе [Подтверждение почты безопасности](../security/email-verification.md).
- **Переключить вход по паролю**: `PUT /api/auth/profile/password-login`
- Отключить пароль можно только при наличии основного Passkey или стороннего аккаунта. Для включения пароль должен быть
  задан.

### Сброс пароля по коду из письма

Отдельная страница `/account/forgot-password` проверяет личный адрес, сохранённый в аккаунте. При отключённой почте
страница и API запроса и подтверждения возвращают `404`, а страницы входа и восстановления скрывают ссылки.
Офлайн-восстановление `/account/recovery` остаётся доступным.

- **Доступность**: `GET /api/auth/password-reset/status` возвращает `{"enabled":true}` или `{"enabled":false}`.
- **Отправка кода**: `POST /api/auth/password-reset/request` принимает `{"email":"admin@example.com"}` и возвращает
  `202` с `{id,status,ticket}` после надёжной записи в очередь, до отправки.
- **Доставка**: `GET /api/auth/mail/:id` принимает закрытый билет в заголовке `X-Renop-Mail-Ticket`. Страница проверяет
  состояние каждые 3 секунды не более 10 минут и прекращает проверку при уходе. Ошибки и неопределённый результат
  показываются пользователю. Принятие провайдером не гарантирует доставку получателю. Не сохраняйте билеты в URL или
  хранилище браузера.
- **Сброс**: `POST /api/auth/password-reset/confirm` принимает JSON ниже. Оба POST требуют
  `Content-Type: application/json`, тело не более 4 096 байт и пароль длиной 6–72 байта UTF-8.

```json
{"email":"admin@example.com","code":"01234567","new_password":"new_secure_password"}
```

Восьмизначный код действует 10 минут и допускает пять ошибок. Помимо настроенного ограничения IP, для адреса действует
задержка 60 секунд между выдачами. Новый код отменяет предыдущий только после успешной записи в очередь; при ошибке
старый сохраняется. Запись письма, кода и счётчика лимита выполняется одной транзакцией. Хранится не более 2 048
подтверждений; просроченные записи удаляются перед добавлением и периодически.

Все допустимые адреса, разрешённые политикой получателей, получают одинаковое письмо проверки владения, включая
незарегистрированные: состояние доставки не раскрывает наличие аккаунта. При сбросе повторно проверяются идентификатор,
почта, пароль и версия безопасности на момент выдачи. Аккаунт, зарегистрированный позднее, не может использовать старый
код; закрытие аккаунта также делает коды недействительными.

Успех атомарно расходует код, меняет пароль, включает вход по паролю и отзывает браузерные сессии. Ответ
`{status:"success",username}` очищает cookie и возвращает страницу ко входу; другие способы входа остаются связанными,
блокировки сохраняются. `ACCOUNT_EMAIL_CODE_INVALID` означает неверный, просроченный, исчерпанный, использованный или
устаревший код. Лимиты возвращают `429`, ошибки очереди или сервиса — `503`. Все ответы используют
`Cache-Control: no-store`.

### Коды восстановления

Отдельная страница восстановления аккаунта `/account/recovery` доступна по ссылке восстановления на странице входа и
работает без отправки почты. После восстановления браузер очищает прежнюю сессию и возвращается ко входу с заполненным
именем пользователя, сохраняя допустимый локальный адрес `return_to`. Коды восстановления и пароли очищаются при уходе
со страницы и не сохраняются в истории браузера.

- **Создать**: `POST /api/auth/profile/recovery-codes`
- **Сбросить пароль**: `POST /api/auth/recovery/password`
- Двенадцать кодов показываются один раз; хранятся только verifier Argon2id. Четыре разных неиспользованных кода
  расходуются атомарно, сессии отзываются, а вход по паролю включается снова.

```json
{
  "identifier": "admin@example.com",
  "codes": ["CODE-ONE", "CODE-TWO", "CODE-THREE", "CODE-FOUR"],
  "new_password": "new_secure_password"
}
```

## Управление способами входа

- **Список Passkey**: `GET /api/auth/profile/fido`
- **Регистрация**: `POST /api/auth/profile/fido/register/begin`, затем
  `POST /api/auth/profile/fido/register/finish`
- **Удаление**: `DELETE /api/auth/profile/fido/:device_id`
- **Связанный GitHub**: `GET /api/auth/profile/github`
- **Отключить GitHub**: `DELETE /api/auth/profile/oauth/github` (`DELETE /api/auth/profile/github`)

Последний рабочий способ входа нельзя удалить или отключить.

## Браузерные сессии

- **Список**: `GET /api/auth/profile/sessions`
- **Отозвать одну**: `DELETE /api/auth/profile/sessions/:session_id`
- **Отозвать остальные**: `POST /api/auth/profile/sessions/revoke-others`

Список содержит публичный ID, способ входа, время, IP и User-Agent, но не секрет cookie.

## Окончательное закрытие учётной записи

`GET /api/auth/profile/retirement` возвращает условия закрытия текущей учётной записи. Этот маршрут и
`DELETE /api/auth/profile/retirement` требуют сеанса браузера. Запрос закрытия принимает JSON:

```json
{"confirmation":"alice"}
```

Подтверждение должно точно совпадать с именем пользователя. Успех возвращает `204 No Content`, несовпадение —
`400` и `ACCOUNT_RETIREMENT_CONFIRMATION`. Невыполненные условия возвращают `409`,
`ACCOUNT_RETIREMENT_BLOCKED` и актуальный план с полями `eligible`, `protected_role`,
`super_team_owner_count`, `maven_domain_owner_count`, `package_owner_count` и `pending_review_count`.

Системные администраторы и модераторы репозиториев не могут закрыть свои учётные записи. Не должно оставаться
ролей T4 глобальных команд, активных доменов Maven во владении, неустаревших пакетов с ролью L4 или ожидающих
проверки заявок. Сначала передайте владение, закройте домены либо окончательно пометьте пакеты устаревшими.

Закрытие навсегда резервирует учётную запись и имя, удаляет членство в командах, освобождает все сторонние привязки
входа
и удаляет Passkey, сеансы, API Token, фото, коды восстановления и сообщения. Вход возвращает
`ACCOUNT_DELETED`. Личный адрес почты резервируется на 14 дней, журнал действий хранится 30 дней.
Плановая очистка обрабатывает истёкшие сроки ограниченными пакетами. Опубликованные пакеты остаются доступными для
скачивания.

Освобождённую внешнюю идентичность можно сразу связать с другой активной учётной записью. Это не освобождает
зарезервированное имя, не сокращает срок удержания почты и не восстанавливает владение закрытыми ресурсами.

Администраторы получают сроки через `GET /api/tokens/:name/retention`, досрочно освобождают почту через
`DELETE /api/tokens/:name/retention/email` и очищают журнал через
`DELETE /api/tokens/:name/retention/audit`. Поля `deleted_at`, `email_release_at`,
`email_released_at`, `audit_purge_at` и `audit_purged_at` содержат миллисекунды Unix.
Административный маршрут `DELETE /api/tokens/:name` применяет те же условия окончательного закрытия.
