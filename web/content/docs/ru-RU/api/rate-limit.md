# Ограничение частоты и защита

RenoP сочетает несколько уровней ограничения частоты и выявления аномалий для защиты от перебора паролей, отказа в
обслуживании и чрезмерного автоматического сбора данных.

## Ограничения для анонимных клиентов

Неаутентифицированные запросы оцениваются по IP с помощью скользящего окна и алгоритма token bucket.

- Для скачивания публичных артефактов действует высокий предел.
- Для поиска и метаданных применяется более строгий предел; при превышении возвращается `429 Too Many Requests`.

## Ошибки аутентификации и блокировка IP

- Серии ответов `401 Unauthorized` или `403 Forbidden` на маршрутах входа и закрытых ресурсах считаются аномальными.
- Соответствующий IP временно блокируется с ответом `403 Forbidden`; при повторениях срок блокировки увеличивается.

## Предел параллельных запросов (`max_active_requests`)

Настройте `server.max_active_requests` в `config.yaml`. Значение по умолчанию — 512.

- Когда число активных запросов достигает предела, новые запросы получают `503 Service Unavailable`.

## Доверенные прокси

При работе за обратным прокси или CDN задайте `server.trusted_proxies` и `server.cdn_ip_header` в `config.yaml`.
RenoP применяет лимиты только к проверенному реальному IP клиента из доверенного источника.
