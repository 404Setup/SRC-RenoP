# API Docker / OCI Registry v2

RenoP реализует OCI Distribution Spec v2 и Docker Registry v2.

Образ контейнера является явным ресурсом. Перед запросом push-прав создайте его через
`POST /api/docker/repositories/:repo/images` или на странице репозитория. Маршруты blob и manifest не создают образ
автоматически. Закрытый образ не попадает в неавторизованные каталоги; для его manifest и связанных blob требуется
участник L0-L4 или администратор.

Создание возвращает `409 Conflict`, если нормализованное имя занято локально или на подходящем включённом зеркале. Если
проверка upstream не дала результата, имя не резервируется и возвращается `503 Service Unavailable`.

API управления возвращает читаемое тело и `X-Renop-Error-Code`; интерфейс переводит код, не показывая сырой текст.
Маршруты OCI используют предписанную спецификацией структуру `errors`.

На странице образа доступен Markdown README уровня пакета. Участник L3/L4 или администратор обновляет его через
`PUT /api/docker/repositories/{repo}/images?image={name}`. JSON-значение `description` ограничено 512 КиБ и
отображается через общий список разрешённых элементов и URL.

## Проверка версии

- **Путь**: `GET /v2/` или `HEAD /v2/`
- **Ответ**:
    - `200 OK` с `Docker-Distribution-API-Version: registry/2.0`;
    - при необходимости входа — `401 Unauthorized` с
      `Www-Authenticate: Bearer realm="http://.../v2/token",service="renop"`.

---

## Аутентификация Bearer Token

- **Путь**: `GET /v2/token` или `GET /v2/auth`
- **Назначение**: обмен Basic Auth на временный Docker Token. API Token требует `repository:read` для pull,
  `repository:publish` для push и `repository:delete` для удаления. Видимость и уровень L0-L4 проверяются отдельно
  перед выдачей каждого действия.

---

## Каталог и теги

### Список образов

- **Путь**: `GET /v2/_catalog`
- **JSON**: `{"repositories": ["my-org/my-app"]}`

### Список тегов

- **Путь**: `GET /v2/:name/tags/list`
- **JSON**: `{"name": "my-org/my-app", "tags": ["latest", "1.0.0"]}`

---

## Операции manifest

- **Чтение**: `GET /v2/:name/manifests/:reference`
- **Публикация**: `PUT /v2/:name/manifests/:reference` (образ создан, уровень не ниже L1)
- **Удаление**: `DELETE /v2/:name/manifests/:reference`

Размер JSON manifest ограничен 4 МиБ. Лимит одинаков для локальной загрузки, ответа зеркала и сохранённого объекта
Disk/S3; превышение отклоняется до разбора или кэширования.
Перед сохранением или выдачей заявленный digest SHA-256 также должен точно соответствовать байтам JSON.

---

## Операции blob

- **Проверка**: `HEAD /v2/:name/blobs/:digest`
- **Скачивание**: `GET /v2/:name/blobs/:digest`
- **Начало**: `POST /v2/:name/blobs/uploads/` (поддерживается `?mount=<digest>&from=<other_repo>`)
- **Добавление блока**: `PATCH /v2/:name/blobs/uploads/:uuid`
- **Завершение**: `PUT /v2/:name/blobs/uploads/:uuid?digest=sha256:...`

## Блокировки ресурсов

Администраторы и модераторы репозитория задают ручную блокировку через
`PUT /api/docker/repositories/{repo}/locks?image={name}` и снимают её через
`DELETE /api/docker/repositories/{repo}/locks?image={name}`. Обе операции требуют действительного cookie браузерной
сессии; API-токены не могут управлять блокировками. Запрос указывает неизменяемый дайджест существующего манифеста;
пустое поле `version` блокирует весь образ.

```json
{"version":"sha256:0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef","mode":"read","reason":"trojan"}
```

Режимы: `write` и `read`. Публичные причины: `hold`, `prohibited`, `expired`, `trojan`, `abuse`, `dmca`, `reup`,
`squatting` и `quality`. Блокировка чтения также запрещает запись: метаданные доступны только администраторам,
модераторам репозитория, владельцам и участникам, включая L0. Загрузка слоёв и конфигураций, а также монтирование из
этого образа запрещены всем. Каталоги, поиск, страницы тегов, профили и ресурсы команд применяют те же правила
видимости.

Блокировка дайджеста охватывает все теги-псевдонимы, дочерние манифесты и blob, на которые ссылается многоархитектурный
индекс. Сохранённые ссылки переживают перезапуск и действуют до снятия исходной блокировки. Ответы раскрывают публичные
поля `locks`, `inherited`, `moderator`, `member` и `version_locked`, но не личность сотрудника. Снятие ручной блокировки
сохраняет системные и унаследованные ограничения. Обработка ограничена 8,192 дайджестами и 64 MiB метаданных; неверный
или слишком большой граф ссылок возвращает `400`, сохраняя прежнюю блокировку.

Запрещённые изменения возвращают `423` и `X-Renop-Error-Code: resource_locked`: переназначение тегов, одобрение
публикации, изменение команды заблокированного образа, удаление или прекращение публикации всего образа при блокировке
любой версии. Удаление и замена общего blob также проверяют блокировки других образов репозитория. Замороженное
содержимое зеркала не обновляется и не заменяется.
