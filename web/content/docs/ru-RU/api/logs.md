# Общие журналы и действия

## Доступ

Откройте **Общие журналы** в панели администратора. Нужна действующая роль системного администратора; API Token также требует `admin:audit`. Роли модератора репозитория недостаточно. Личная история ограничена текущим аккаунтом; администратор может просматривать другой аккаунт.

Инициатор — аккаунт, запросивший операцию; оператор — аккаунт или задача, выполнившие её. Прямые операции и исторические строки используют оператора как инициатора. Обе личности имеют одинаковые ограничения маскирования и личной фильтрации. Источник остаётся в `trigger`. Переименование и закрытие учитывают обе личности.

```http
GET /api/auth/logs?kind=system&severity=error&trigger=http&page=1&page_size=20
GET /api/auth/profile/audit-logs?action=LOGIN&from=1788739200000&until=1788825599999
GET /api/auth/users/alice/audit-logs?operator=admin&trigger=web
```

## Фильтры

Условия объединяются через AND. Текст сравнивается точно, пустое значение отключает фильтр. Время браузера переводится в миллисекунды Unix. Неверные условия возвращают `400` и `LOG_FILTER_INVALID`. Действие и источник ограничены 64 байтами, аккаунт и оператор — 255 байтами.

| Параметр | Значения |
| --- | --- |
| `kind` | `audit`, `system` |
| `action` | Точный идентификатор действия, например `LOGIN`, `SYSTEM_LOG`, `SYSTEM_HTTP_ERROR` |
| `operator` | Точное имя; личный просмотр также принимает `@administrator` |
| `initiator` | Точное имя; личный просмотр также принимает `@administrator` |
| `username` | Затронутый аккаунт, только общий просмотр |
| `trigger` | Точный источник `web`, `api`, `http`, `system`, `unknown` |
| `severity` | `info`, `warning`, `error` |
| `from`, `until` | Миллисекунды Unix включительно; любую границу можно опустить |
| `page`, `page_size` | По умолчанию `1`, `20`; размер `1`–`200`; смещение не более `1000000` |

## Видимость

Существующий protobuf `AuditLogList` расширен полями `kind`, `trigger`, `initiator`, `severity`. Личный и поимённый журналы ограничены типом `audit`. Другие операторы скрыты как Администратор; `operator=@administrator` выбирает эту группу. Любое другое имя, включая несуществующее, возвращает `400`, поэтому фильтры не раскрывают скрытых администраторов. Параметр `username` не расширяет область аккаунта.

## Системная диагностика

После запуска фоновых служб перехватываются журналы процесса и ошибки HTTP-сервера. Детали не передаются публичным клиентам. Типичные пароли, заголовки авторизации, токены и учётные данные URL скрываются перед записью; предел записи — 4096 байт. Старые производители определяют источник по способу авторизации, перенесённые записи используют `unknown`. Уровень неструктурированных сообщений определяется по ключевым словам, структурированные ошибки HTTP используют `error`.

## Хранение и запись

Один потребитель последовательно сохраняет записи. При штатном завершении исходный вывод восстанавливается, очередь до 500 записей опустошается. При переполнении действия используют прежнюю синхронную запись; сообщения системы остаются в исходном выводе, увеличивают счётчик сбоев и создают уведомление после освобождения очереди. Ошибки записи идут только в исходный вывод, исключая рекурсию. Действия сохраняют лимиты `audit_log`; система имеет отдельный бюджет не более 30 дней и 10000 строк, либо меньшие настроенные пределы. Очистка выполняется каждые десять минут. Сроки закрытия аккаунтов и окончательная очистка действуют и для связанных системных записей. Исторические журналы процесса не импортируются.
