# API обращений

Обращения объединяют отзывы, предложения, жалобы, передачу владения и одобрение публикаций в одном постоянном процессе. Центр обращений заменяет центр проверок, сохраняя идентификаторы задач и ожидающие публикации.

## Область и учётные данные

Каждый маршрут требует действующий браузерный cookie `renop_session`. Basic, Bearer API Token и сессионные токены без этого cookie отклоняются. Откройте `/account/tickets`; старые ссылки `/account/reviews` перенаправляются туда.

Модераторы видят все состояния обращений своих репозиториев, включая командный этап. Системные администраторы видят все области. Участники T3/T4 обрабатывают только назначенные своей команде передачи и создания. Командное одобрение по-прежнему предшествует проверке репозитория. История заявителя связана с неизменяемой идентичностью аккаунта.

Уполномоченные сотрудники видят личности коллег внутри обращения. Заявителю никогда не возвращаются `assignee`, `escalated_by` и `decided_by`. Аккаунт, на который подана жалоба, не может читать или обрабатывать её даже с правами администратора. Объект жалобы не получает личность заявителя или доступ к обращению.

Напоминания следуют текущему этапу. Итог отправляется заявителю сообщением и, если включено, письмом на языке аккаунта. Объект жалобы получает отдельное уведомление только после завершения с `upheld`: ресурс и результат, без ID обращения, заявителя, сотрудника или закрытого текста. Отказ и отзыв не уведомляют объект жалобы. Идентификаторы почтовых сценариев сохраняют совместимость.

Аудит жалоб не содержит идентичность аккаунта, сотрудника, сессии или IP; сведения об исполнителях остаются внутри доступных по правам обращений.

## Отправка отзыва, предложения или жалобы

POST /api/tickets принимает `kind` (`feedback`, `suggestion` или `report`), `title` (1–160 символов), `body` (1–8000 символов) и необязательный `repository`. JSON ограничен 48 KiB. Аккаунт может иметь 16 ожидающих запросов поддержки и создавать 24 за 24 часа; общий предел всех процессов — 4096 ожидающих задач.

Жалоба также требует `target`: `format`, `repository`, `name` и необязательный `version`. Форматы: `user`, `superteam`, `maven-domain`, `maven`, `cargo`, `npm`, `docker`. Глобальные ресурсы не задают репозиторий. Пакет должен соответствовать формату репозитория и быть доступен для чтения. Можно сообщить о другом пользователе, видимом пакете или версии, домене публикации либо команде; свои ресурсы, скрытые объекты и повторные ожидающие жалобы отклоняются.

Создание возвращает `201`, обращение и `Location`. Владельцы объекта сохраняются по неизменяемым ID аккаунтов. Запись `upheld` сама не блокирует аккаунт или пакет: перед фиксацией обоснованной санкции примените соответствующее существующее действие модерации.

```json
{"kind":"report","title":"Package report","body":"Please investigate this version.","target":{"format":"npm","repository":"npm","name":"@platform/tool","version":"1.0.0"}}
```

## Принятие, эскалация и решение

POST /api/tickets/{id}/action принимает `action`: `claim`, `release`, `escalate`, `process`, `complete` или `close`. До обработки или решения сотрудник должен принять обращение. Принятие атомарно; остальные сохраняют чтение, но не могут обрабатывать. Системный администратор может указать `force: true` и забрать обращение модератора, но не другого администратора, который ещё не освободил его.

Эскалация освобождает обращение и разрешает следующее принятие только системным администраторам. Администратор может передать его другому администратору. Разрешены три эскалации. После третьей следующий исполнитель обязан закончить: освобождение, дальнейшая эскалация и принудительный перехват отключены. Командное одобрение освобождает назначение для этапа репозитория.

Для поддержки `process` отмечает обработку без итогового уведомления, `complete` завершает, а `close` закрывает. Требуется непустой `response` до 4096 символов. Отзывы и предложения используют `outcome: resolved`, жалобы — `upheld` или `dismissed`, закрытие записывает `closed`. JSON действия ограничен 24 KiB. Публикации и передачи после принятия используют маршрут решения ниже.

GET /api/tickets/{id} возвращает доступные подробности и массив `actions`, вычисленный по текущим правам и назначению; используйте его для элементов управления. Конфликты назначения возвращают `409` с `ticket_claim_required`, `ticket_occupied` или `ticket_escalation_limit`.

## Правила передачи

Заявитель должен иметь эффективный уровень L4 для проекта или домена либо действующие полномочия администратора
репозитория/системы. Для передачи глобальной команде он также должен быть её участником. Решение принимает администратор
T3/T4 проверяющей команды или системный администратор; заявитель с такими правами может обработать свою задачу.

Передача меняет только привязку владельца. Участники уровня пакета не копируются и не удаляются. Прямая передача между
двумя командами запрещена: допустимый проект сначала возвращают в личное владение, затем создают отдельный запрос.

Образы Docker с пространством имён и пакеты npm со scope нельзя вернуть в личное владение, поскольку имя резервирует
неизменяемый префикс команды. Ресурсы, полученные из зеркала, также нельзя передавать.

## Правила публикации

Репозиторий Maven может отключить проверку, проверять только первую версию нового артефакта или проверять каждую версию.
Включение проверки отключает повторное развертывание. Локальные файлы сохраняются, но не попадают в публичный индекс до
решения модератора репозитория или системного администратора. Зеркальные загрузки не проверяются.

Если обязательны отделённые подписи GPG, сначала завершается их проверка. Контрольные суммы, подписи и метаданные Maven
одной версии объединяются в одну задачу. Решение недоступно пять секунд после последнего файла, чтобы клиент успел
завершить загрузку. После одобрения добавлять файлы к версии нельзя.

Для npm участник T2 всегда начинает с одобрения T3/T4 команды без резервирования имени. Если включена проверка создания
в репозитории, та же задача переходит к модератору; иначе пакет создаётся атомарно. На окончательном этапе повторно
проверяются права репозитория и текущее участие в команде, после чего заявителю выдаётся L4. В режиме `new_packages`
следующие версии публикуются обычно. В режиме `every_version` каждый tarball и ограниченный manifest с dist-tag также
скрываются до одобрения. Зеркальный контент задач не создаёт.

Публикация Cargo сохраняет и скрывает архив crate, не изменяя sparse index и публичный каталог. При одобрении
неизменяемая версия добавляется в оба набора метаданных до открытия архива; при отклонении скрытый архив удаляется.
В режиме `new_packages` crate считается новым до одобрения первой видимой версии. Зеркальные crates проверку не
проходят.

Для Docker запрос T2 проходит те же последовательные этапы команды и, при необходимости, репозитория, что и npm.
Окончательное одобрение повторно проверяет локальные и upstream-конфликты, права репозитория и текущее участие в
команде перед резервированием image. В режиме `new_packages`
следующие manifests публикуются обычно. В режиме `every_version` точные байты каждого manifest остаются ограниченным
виртуальным файлом до одобрения, а reference и tag не попадают в каталог. Существующий tag того же digest не скрывается;
manifest, ссылки blobs, tag и решение записываются атомарно. Импорт из зеркала проверку не проходит.

## Список задач

GET /api/tickets возвращает ограниченную страницу. `view` принимает `reviewer` или `requested`; `status` — `unprocessed` (по умолчанию), `in_progress`, `processed`, `closed`, `completed` или `all`. `limit` равен 1–100, `offset` неотрицателен. Фильтр `types` через запятую принимает типы процессов и `support`, `user`, `superteam`, `maven-domain`, `maven`, `cargo`, `npm`, `docker`.

`ticket_status` описывает общий жизненный цикл. Прежний `status` сохраняет результат процесса: `pending`, `approved`, `rejected` или `cancelled`. Исторические записи получают состояние обращения при первом принятии.

Ответ содержит `tasks`, `total`, `limit`, `offset` и итоговый `view`. Задача хранит исходный, целевой и текущий
проверяющий префиксы, отображаемое имя заявителя, время, состояние и сведения о завершённом решении. Непустой
`review_team_prefix` назначает задачу участникам T3/T4 этой команды. После командного одобрения создания T2 поле
очищается, а задача остаётся `pending` для проверки репозитория.
Для публикации также возвращаются `resource_version`, `file_count`, `total_size` и время последнего файла.
Явное создание npm/Docker использует зарезервированное значение `@create` в `resource_version` и предоставляет
ограниченный JSON-запрос через тот же файловый API.

## Запрос передачи

POST /api/tickets/super-team-transfers принимает `resource_type`, `repository`, `resource_key` и
`target_team_prefix`. Для домена Maven поле `repository` пропускается. Артефакт Maven использует ключ
`groupId:artifactId`. Пустая целевая команда означает возврат в личное владение.

Для одного ресурса может ожидать только одна передача владения независимо от выбранной цели. Создание возвращает
`201 Created`, тело задачи и её расположение в API.

## Файлы проверки

GET /api/tickets/{id}/files возвращает до 256 относительных путей со стабильным идентификатором, размером, временем
загрузки и признаком ключевого файла. GET /api/tickets/{id}/files/{file_id} передаёт один скрытый файл. Доступ имеют
только заявитель, T3/T4 текущей проверяющей команды, модератор соответствующего репозитория и системный
администратор с браузерной сессией.

Веб-интерфейс использует до четырёх адаптивных потоков и повторяет каждую ошибку два раза. После успешной загрузки он
создаёт ZIP со стандартными путями репозитория прямо в браузере. При повторной ошибке ключевые файлы открываются
отдельно, а неполный архив не создаётся.

## Решение или отмена

Текущий сотрудник должен принять обращение на этом этапе. POST /api/tickets/{id}/decision принимает `approved` или `rejected`. Одобрение создания T2 либо завершает создание,
либо возвращает ту же задачу со статусом `pending` и пустым `review_team_prefix`, если требуется проверка репозитория.
Отказ в передаче требует причину до 512 символов.
Отказ в публикации требует `reason_code`: `invalid_metadata`, `quality`, `policy_violation`, `copyright`, `malware`
или `custom`. Собственная причина ограничена 505 символами. При одобрении метаданные версии соответствующего движка
создаются до открытия файлов; при отказе скрытые файлы удаляются.

DELETE /api/tickets/{id} позволяет заявителю отозвать ожидающий запрос поддержки, передачи владения или восстановления Maven. Обращение закрывается, дальнейшие решения запрещены. Публикации этим маршрутом не отменяются. Конкурентные итоговые решения не могут дважды изменить ресурс.

## Обработка ошибок

Ошибка содержит стабильный `X-Renop-Error-Code`. `400` обозначает неверный фильтр, идентификатор ресурса или решение.
`403` означает отсутствие владения, участия в целевой команде либо полномочий проверяющего. `404` означает отсутствие
задачи или файла. `409` покрывает дубликат, завершённую задачу, изменение владельца, запрещённую передачу или
публикацию,
которая ещё принимает файлы.

Клиент должен локализовать зарегистрированный код и не показывать тело ответа напрямую.

## Восстановление пакета Maven после повторной заявки

`POST /api/tickets/maven-restorations` требует действующий cookie `renop_session` текущего владельца L4 домена:

```json
{"resource_type":"maven_artifact","repository":"releases","resource_key":"com.example:demo"}
```

Ответ HTTP `201` содержит задачу `maven_restore` со статусом `pending`; эквивалентная ожидающая заявка возвращает `409`.
Задачу видят модераторы репозитория и системные администраторы. Используются существующие маршруты решения и отмены.
Одобрение атомарно проверяет заявку на домен, действующее владение и независимые блокировки, затем возвращает публикацию и связь с текущей командой домена.
Изменение заявки отменяет устаревший запрос. Отказ или отмена сохраняет ограничение пакета и загрузки.
Разрешено до 64 ожидающих запросов на аккаунт и 4096 всего. У таких задач нет архива файлов для скачивания.
