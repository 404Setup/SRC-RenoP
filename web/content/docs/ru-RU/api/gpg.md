# Подписи GPG

RenoP проверяет отделённые подписи OpenPGP для Maven-артефактов. Политика GPG распространяется на файлы `.jar`,
`.pom` и `.module`. Запись о подписи сохраняется только после проверки ключом, зарегистрированным для учётной записи,
выполнившей загрузку.

## Настройка

Укажите от одного до восьми HTTPS-серверов ключей в `server.gpg.key_servers` файла `config.yaml`. То же значение
доступно через поле `server.gpg` API настроек. При регистрации ключа RenoP использует эти серверы для разрешения ID
ключа или отпечатка. См. [обзор конфигурации](../configuration/overview.md) и [API настроек](./settings.md).

Для обязательной проверки подписей задайте в репозитории `require_gpg_signature: true`. Параметр относится к трём
защищённым расширениям; файлы контрольных сумм и сопутствующие файлы Maven-метаданных обрабатываются в рамках той же
публикации. Подробности приведены в разделе [Репозитории и зеркала](../configuration/repositories.md).

## Регистрация ключа

Аутентифицированный пользователь может зарегистрировать в профиле до десяти открытых ключей:

| Метод    | Эндпоинт                             | Результат                           |
|----------|--------------------------------------|-------------------------------------|
| `GET`    | `/api/auth/profile/gpg`              | `GpgKeyList`                        |
| `POST`   | `/api/auth/profile/gpg`              | `GpgKeyDto`                         |
| `DELETE` | `/api/auth/profile/gpg/:fingerprint` | Пустой ответ `204`                  |
| `GET`    | `/api/auth/profile/gpg/releases`     | История публикаций `GpgReleaseList` |

Тело запроса `POST` имеет тип `GpgKeyReferenceRequest` (`application/x-protobuf`):

```protobuf
syntax = "proto3";

message GpgKeyReferenceRequest {
  string key_id = 1;
}
```

Если короткий ID ключа неоднозначен, укажите полный отпечаток. Сервер сохраняет найденный открытый ключ в базе данных и
не принимает закрытые ключи. Эти эндпоинты требуют аутентификации; историю публикаций видит только соответствующий
пользователь.

## Загрузка подписанного артефакта

Загрузите артефакт и его отделённую подпись по одному и тому же Maven-пути. Имя файла подписи должно состоять из имени
артефакта с добавленным суффиксом `.asc` в нижнем регистре, например `demo-1.0.0.jar.asc`.

При загрузке артефакта одним запросом установите `X-RenoP-GPG-Signature-Expected: true`, если соответствующая подпись
входит в тот же пакет загрузки:

```bash
curl -u alice:TOKEN \
  -H 'X-RenoP-GPG-Signature-Expected: true' \
  -T demo-1.0.0.jar \
  'https://repo.example/releases/com/example/demo/1.0.0/demo-1.0.0.jar'

curl -u alice:TOKEN \
  -T demo-1.0.0.jar.asc \
  'https://repo.example/releases/com/example/demo/1.0.0/demo-1.0.0.jar.asc'
```

Для поэтапной загрузки укажите `gpg_signature_expected: true` в `ChunkedUploadInitRequest` вместо HTTP-заголовка. Форма
загрузки в браузере устанавливает этот флаг автоматически, обнаружив соответствующий файл `.asc`.

Подпись должна быть подписью OpenPGP в формате ASCII Armor размером не более 1 МиБ. Ключ подписи должен быть
зарегистрирован пользователем, выполняющим загрузку. Если репозиторий требует подпись или загрузка явно сообщает о
необходимости подписи, артефакт остаётся в карантине GPG до проверки пары. Неполная пара истекает примерно через 15
минут и записывается как неудачная публикация.

Если подписи необязательны и флаг ожидания не указан, артефакт публикуется как неподписанный файл. Последующая загрузка
`.asc` всё ещё может создать подтверждённую запись о подписи. Замена артефакта аннулирует прежнюю запись, если новая
публикация не прошла проверку.

## Просмотр результата проверки

### `GET /api/maven/signatures/:repo_name/*`

Для проверенного артефакта `.jar`, `.pom` или `.module` возвращает `GpgSignatureDetails` (`application/x-protobuf`).
Требуется право чтения репозитория. Если запись отсутствует, расширение не поддерживается или артефакт недоступен,
возвращается `404`.

| Поле                                      | Значение                                         |
|-------------------------------------------|--------------------------------------------------|
| `repository` / `artifact_path`            | Репозиторий и относительный Maven-путь артефакта |
| `fingerprint` / `key_id`                  | Идентификаторы открытого ключа подписи           |
| `primary_identity`                        | Основная идентичность найденного открытого ключа |
| `uploader`                                | Учётная запись, отправившая публикацию           |
| `signature_created_at` / `verified_at`    | Временные метки Unix в миллисекундах             |
| `hash_algorithm` / `public_key_algorithm` | Алгоритмы, записанные при проверке               |

Поле `FileDetails.signed` имеет значение `true` только при наличии подтверждённой записи о подписи для файла. В браузере
для подписанных артефактов появляется кнопка со значком замка; нажатие открывает диалог сведений о подписи и загружает
данные указанного эндпоинта. Предварительный просмотр поддерживаемых текстовых файлов сохраняется, включая `.pom` и
`.module`.

Неудачные публикации и причины доступны владельцу через `GET /api/auth/profile/gpg/releases`. Возможные состояния:
`queued`, `validating`, `success` и `failed`.
