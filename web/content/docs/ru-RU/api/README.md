# HTTP API RenoP

RenoP предоставляет HTTP API для автоматизации администрирования, интеграции клиентов и мониторинга. По умолчанию
сервер слушает `http://localhost:3000`.

## Структура маршрутов

| Префикс                         | Назначение                                                        |
|:--------------------------------|:------------------------------------------------------------------|
| `/api/*`                        | Управление аутентификацией, аккаунтами, настройками и сообщениями  |
| `/{repo}/*`                     | Загрузка, скачивание и удаление с учётом формата репозитория       |
| `/index/*` или `/{repo}/index/*` | Cargo Sparse Index                                               |
| `/v2/*`                         | Docker и OCI Distribution v2                                     |
| `/javadoc/*`                    | Изолированный просмотр Javadoc                                    |
| `/cargodoc/*`                   | Изолированный просмотр Cargodoc                                   |

## Форматы данных и Protobuf

Большинство API управления используют JSON. Высокопроизводительные маршруты также поддерживают Google Protocol
Buffers с типом `application/x-protobuf`.

Для соответствующих маршрутов задайте `Accept: application/x-protobuf` или
`Content-Type: application/x-protobuf`. Исходный контракт находится в `proto/api/v1/api.proto`.

## Способы аутентификации

1. **Cookie браузера**: `renop_session=<session_id>`. Секрет HttpOnly не принимается в заголовках или URL.
2. **Bearer API Token**: `Authorization: Bearer <token>`. Возможности Token всегда пересекаются с текущими правами
   аккаунта.
3. **Basic Auth для пакетных протоколов**: `Authorization: Basic <base64(user:password_or_token)>`.

Basic Auth не позволяет обращаться к API управления. Учётные данные в URL и `Authorization: Session` отклоняются.

## Основные коды HTTP

| Код                       | Значение             | Назначение                                               |
|:--------------------------|:---------------------|:---------------------------------------------------------|
| `200 OK`                  | Успех                | Успешный ответ с телом                                    |
| `201 Created`             | Создано              | Ресурс или загрузка инициализированы                      |
| `204 No Content`          | Успех                | Успешный ответ без тела                                   |
| `400 Bad Request`         | Неверный запрос      | Некорректные параметры или тело                           |
| `401 Unauthorized`        | Нет аутентификации   | Учётные данные отсутствуют или неверны                    |
| `403 Forbidden`           | Доступ запрещён      | Недостаточно прав или IP временно заблокирован            |
| `404 Not Found`           | Не найдено           | Ресурс отсутствует                                        |
| `409 Conflict`            | Конфликт             | Несовместимое состояние или ресурс уже существует         |
| `429 Too Many Requests`   | Ограничение частоты  | Превышена допустимая частота запросов                      |
| `503 Service Unavailable` | Временно недоступно  | Перегрузка или временная недоступность зависимости        |
