# Глобальные команды

Глобальная команда — общая для instance identity совместной публикации. Её неизменяемый префикс используется разными
package engines без копирования участников в команды каждого пакета. Внутри хранятся immutable account IDs, а API
показывает только usernames.

## Роли и владение

T1 читает согласно видимости пакета. T2 публикует и сопровождает версии, а также может запросить создание пакета npm
или образа Docker для команды. Такой запрос должен одобрить участник T3 или T4. T3 управляет участниками T1/T2 и может
создавать пакеты сразу. T4 владеет настройками и выдаёт T3/T4.

Должен оставаться хотя бы один T4. T3 не может менять или выдавать T3/T4. System administrator управляет любой командой
без вступления, но при добавлении проверяется лимит целевого аккаунта. Добавление самого администратора не создаёт
лишнее сообщение.

## Привязка проектов и доменов

GET /api/super-teams/eligible по умолчанию возвращает команды с уровнем не ниже T3; `minimum_role` принимает T1-T4.
Диалоги создания npm и Docker запрашивают T2, чтобы подходящий участник мог отправить задачу на проверку. Образ Docker
с косой чертой должен выбрать команду первого компонента пути. Пакет npm с областью должен выбрать команду области без
`@`. Имена без префикса могут оставаться личными.

Запрос T2 не резервирует имя. Одобрение T3/T4 команды является первым этапом. Если репозиторий также проверяет новые
пакеты, та же задача затем переходит к модераторам, а имя остаётся свободным до окончательного одобрения. Ни одна из
границ полномочий не может обойти другую.

Та же привязка применяется к пакетам Cargo, артефактам Maven и доменам публикации Maven. Действующий уровень — больший
из явного разрешения пакета и отображенного уровня команды. Участники команды не копируются в таблицы участников
пакетов. Команду нельзя удалить, пока все принадлежащие ей проекты и домены не перенесены или не удалены.
Владелец L4 подаёт запрос в `/account/tickets`; администратор T3/T4 команды или системный администратор принимает одно
решение.

## Лимиты

Значения `super_teams.create_limit` и `super_teams.join_limit` по умолчанию равны пяти и двадцати. Собственная команда
учитывается в обоих счётчиках.

GET /api/super-teams/limits возвращает эффективные лимиты. Manager использует GET
/api/super-teams/users/{username}/limits и PUT /api/super-teams/users/{username}/limits для индивидуальных значений.
`-1` означает наследование, ноль запрещает операцию. GET /api/settings/super-teams и PUT /api/settings/super-teams
изменяют глобальные значения.

## Жизненный цикл

GET /api/super-teams возвращает страницу по префиксу. Обычный аккаунт видит свои команды, administrator — все. POST
/api/super-teams резервирует префикс и назначает caller роль T4. Префикс имеет длину 2–64, состоит из строчных букв,
цифр, дефисов и подчёркиваний, начинается и заканчивается буквой или цифрой и не меняется.

GET /api/super-teams/{prefix} возвращает metadata и usernames участников. PUT /api/super-teams/{prefix} меняет имя и
описание. DELETE /api/super-teams/{prefix} удаляет команду и атомарно отменяет pending invitations.

## Работа с участниками

POST /api/super-teams/{prefix}/members принимает от одного до двадцати usernames и роль T1-T4. Обычный manager создаёт
одноразовое приглашение message center на семь дней; system administrator добавляет сразу.

PUT /api/super-teams/{prefix}/members/{username} меняет роль. DELETE /api/super-teams/{prefix}/members/{username}
удаляет участника или выполняет выход. POST /api/super-teams/invitations/{id}/{decision} принимает `accept` или `reject`
и не допускает двойного применения при повторном или конкурентном ответе.

## Границы API Token

Маршруты требуют `team:manage`, exact target имеет вид `global/{prefix}`. Чтение лимита требует `account:read`,
индивидуальная настройка — `admin:users`, глобальная — `admin:settings`. Targeted Token не может перечислить все команды
или создать другой префикс.

Ошибки возвращают стабильный `X-Renop-Error-Code` и bounded generic body. Client должен использовать HTTP status и
зарегистрированный code, а не показывать raw response text.

## Блокировка ресурсов

Системные администраторы и глобальные модераторы (`canmoderate:*`) могут блокировать команду с действующим cookie браузерной сессии. Права модератора отдельного репозитория не разрешают изменять глобальную команду; API-токены не могут управлять блокировками.

- `PUT /api/super-teams/{prefix}/locks`
- `DELETE /api/super-teams/{prefix}/locks`

```json
{"mode":"read","reason":"abuse"}
```

Оба режима запрещают изменение данных команды, состава участников, принятие приглашений, переопределение квот, передачу владения, создание и изменение связанных ресурсов. `write` сохраняет загрузки. `read` скрывает команду от посторонних и оставляет метаданные пакетов доступными только уполномоченным сотрудникам и существующим владельцам/участникам, включая T1; содержимое файлов недоступно всем. Списки участников и роли сохраняются. Блокировка команды домена Maven охватывает и неиндексированные пути; независимо подтверждённые дочерние домены сохраняют собственные полномочия.

Списки и сведения о команде содержат публичные `locks`; поле `moderator` отражает права текущего запроса и не даёт полномочий управления командой. Страницы аккаунта и публичные страницы показывают переведённые причины и действия сотрудников. DELETE принимает `{}` и снимает только ручную блокировку; системные блокировки независимы. Запрещённая запись возвращает `423` и `X-Renop-Error-Code: resource_locked`, скрытый ресурс — `404`. Снятие блокировки восстанавливает сохранённые права с учётом других действующих ограничений.
