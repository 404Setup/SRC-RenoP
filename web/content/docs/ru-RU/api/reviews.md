# API проверок

API проверок отделяет передачу владения и модерируемые публикации от центра сообщений. Задачи хранятся постоянно, выдаются постранично и могут
получить только одно решение. Поддерживаются образы Docker, пакеты npm, крейты Cargo, артефакты Maven и домены
публикации Maven.

## Область и учётные данные

Маршруты проверок принимают только аутентифицированную браузерную сессию. Basic-данные и Bearer API Token не могут
создавать, читать, решать или отменять задачи. То же представление открывается из меню аккаунта по адресу
`/account/reviews`.

Представление проверяющего содержит передачи команд, где аккаунт имеет роль T3/T4, и публикации репозиториев, где он
назначен модератором. Системный администратор видит все задачи. Представление заявителя использует неизменяемый
идентификатор аккаунта, поэтому сохраняет записи после смены имени пользователя.

## Правила передачи

Заявитель должен иметь эффективный уровень L4 для проекта или домена либо действующие полномочия администратора
репозитория/системы. Для передачи глобальной команде он также должен быть её участником. Решение принимает администратор
T3/T4 проверяющей команды или системный администратор; заявитель с такими правами может обработать свою задачу.

Передача меняет только привязку владельца. Участники уровня пакета не копируются и не удаляются. Прямая передача между
двумя командами запрещена: допустимый проект сначала возвращают в личное владение, затем создают отдельный запрос.

Образы Docker с пространством имён и пакеты npm со scope нельзя вернуть в личное владение, поскольку имя резервирует
неизменяемый префикс команды. Ресурсы, полученные из зеркала, также нельзя передавать.

## Правила публикации

Репозиторий Maven может отключить проверку, проверять только первую версию нового артефакта или проверять каждую версию.
Включение проверки отключает повторное развертывание. Локальные файлы сохраняются, но не попадают в публичный индекс до
решения модератора репозитория или системного администратора. Зеркальные загрузки не проверяются.

Если обязательны отделённые подписи GPG, сначала завершается их проверка. Контрольные суммы, подписи и метаданные Maven
одной версии объединяются в одну задачу. Решение недоступно пять секунд после последнего файла, чтобы клиент успел
завершить загрузку. После одобрения добавлять файлы к версии нельзя.

Публикация npm уже является одной полной транзакцией. RenoP скрывает tarball и хранит ограниченный manifest с dist-tag
до одобрения, после чего вместе записывает неизменяемую версию и теги. В режиме `new_packages` резервирование считается
новым пакетом до одобрения первой видимой версии. Зеркальные packument и tarball задач не создают.

## Список задач

GET /api/reviews возвращает ограниченную страницу. `view` принимает `reviewer` или `requested`; `status` принимает
`pending`, `approved`, `rejected`, `cancelled` или `all`. Необязательный `types` задаёт через запятую один или несколько
из пяти типов ресурсов. `limit` находится от 1 до 100, а `offset` не может быть отрицательным.

Ответ содержит `tasks`, `total`, `limit`, `offset` и итоговый `view`. Задача хранит исходный и целевой префиксы,
отображаемое имя заявителя, время, состояние и сведения о завершённом решении.
Для публикации также возвращаются `resource_version`, `file_count`, `total_size` и время последнего файла.

## Запрос передачи

POST /api/reviews/super-team-transfers принимает `resource_type`, `repository`, `resource_key` и
`target_team_prefix`. Для домена Maven поле `repository` пропускается. Артефакт Maven использует ключ
`groupId:artifactId`. Пустая целевая команда означает возврат в личное владение.

Для одного ресурса может ожидать только одна передача владения независимо от выбранной цели. Создание возвращает
`201 Created`, тело задачи и её расположение в API.

## Файлы проверки

GET /api/reviews/{id}/files возвращает до 256 относительных путей со стабильным идентификатором, размером, временем
загрузки и признаком ключевого файла. GET /api/reviews/{id}/files/{file_id} передаёт один скрытый файл. Доступ имеют
только заявитель, назначенный модератор репозитория и системный администратор с браузерной сессией.

Веб-интерфейс использует до четырёх адаптивных потоков и повторяет каждую ошибку два раза. После успешной загрузки он
создаёт ZIP со стандартными путями репозитория прямо в браузере. При повторной ошибке ключевые файлы открываются
отдельно, а неполный архив не создаётся.

## Решение или отмена

POST /api/reviews/{id}/decision принимает `approved` или `rejected`. Отказ в передаче требует причину до 512 символов.
Отказ в публикации требует `reason_code`: `invalid_metadata`, `quality`, `policy_violation`, `copyright`, `malware`
или `custom`. Собственная причина ограничена 505 символами. При одобрении метаданные версии соответствующего движка
создаются до открытия файлов; при отказе скрытые файлы удаляются.

DELETE /api/reviews/{id} позволяет заявителю отменить только ожидающую передачу владения. Публикацию через этот маршрут
отменить нельзя. Сравнение и замена ожидающего состояния гарантирует, что конкурентное решение получит конфликт.

## Обработка ошибок

Ошибка содержит стабильный `X-Renop-Error-Code`. `400` обозначает неверный фильтр, идентификатор ресурса или решение.
`403` означает отсутствие владения, участия в целевой команде либо полномочий проверяющего. `404` означает отсутствие
задачи или файла. `409` покрывает дубликат, завершённую задачу, изменение владельца, запрещённую передачу или публикацию,
которая ещё принимает файлы.

Клиент должен локализовать зарегистрированный код и не показывать тело ответа напрямую.
