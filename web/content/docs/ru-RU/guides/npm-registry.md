# Руководство по реестру npm

Создайте репозиторий формата `npm`, затем зарезервируйте каждый пакет на странице репозитория до публикации. RenoP не
разрешает клиенту неявно создавать имя. В примерах используются репозиторий `javascript` и пакет `@example/library`.

## Настройка клиента

Создайте срок действия API Token с правами чтения и публикации. Права жизненного цикла и управления командой нужны
только соответствующей автоматизации. Для выделенного реестра добавьте в проектный или пользовательский `.npmrc`:

```ini
registry=https://packages.example.com/javascript/
//packages.example.com/javascript/:_authToken=${RENOP_NPM_TOKEN}
always-auth=true
```

Чтобы направить в RenoP только одну область, сохраните реестр по умолчанию и настройте область отдельно:

```ini
@example:registry=https://packages.example.com/javascript/
//packages.example.com/javascript/:_authToken=${RENOP_NPM_TOKEN}
always-auth=true
```

Вне доверенной локальной сети используйте HTTPS. Для автоматизации предпочтителен API Token; пароль аккаунта
ограничен аутентификацией стандартных протоколов пакетов.

## Подготовка и публикация пакета

Зарезервированное имя должно точно совпадать с `name` в `package.json`. Версии соответствуют SemVer и после успешной
публикации неизменяемы.

```json
{
  "name": "@example/library",
  "version": "1.0.0",
  "description": "Example library",
  "publishConfig": {
    "registry": "https://packages.example.com/javascript/"
  }
}
```

Публикуйте и устанавливайте пакет любым совместимым клиентом:

```bash
npm publish
npm install @example/library
pnpm add @example/library
yarn add @example/library
bun add @example/library
```

RenoP проверяет ограниченный gzip tarball, сверяет `package/package.json` с запросом, вычисляет совместимые с npm
SHA-1 и SHA-512 integrity и фиксирует архив только после успешной проверки.

Если включена проверка публикаций, успешный `npm publish` возвращает ответ о принятии, но версия ещё отсутствует в
packument и маршрутах tarball. Модератор репозитория или системный администратор проверяет тот же неизменяемый manifest,
dist-tag и tarball в `/account/reviews`; при одобрении они публикуются вместе.

## Видимость и команда пакета

Публичные пакеты наследуют видимость репозитория. Приватный пакет обязан иметь scope и доступен только явным участникам
или администраторам. L0 читает, L1 публикует, L2 управляет версиями и метаданными, L3 управляет командой, L4 владеет
пакетом. Удаление или понижение не может убрать последнего владельца L4.

Приглашайте существующие аккаунты RenoP со страницы пакета. Приглашение хранится в центре сообщений. Зеркальный пакет
не имеет локальной команды, отмечается источником и всегда доступен только для чтения.

## Dist-tag, устаревание и снятие публикации

Стандартные команды npm управляют тегами распространения и сведениями об устаревании:

```bash
npm dist-tag add @example/library@1.0.0 stable
npm deprecate @example/library@1.0.0 "Use version 2"
npm unpublish @example/library@1.0.0
```

Снятие публикации создаёт tombstone и удаляет tarball, но номер нельзя использовать повторно. Удаление пакета отмечает
все версии и сохраняет имя зарезервированным.

## Вышестоящие зеркала

Репозиторий npm может проксировать упорядоченный внешний реестр. Точные имена и `@scope/*` ограничивают зеркало. RenoP
ограничивает packument, объединяет параллельные обновления, заменяет URL tarball локальными и удаляет из локального
каталога версии, исчезнувшие во внешнем реестре. Пакеты, обнаруженные зеркалом, не принимают локальные публикации.
